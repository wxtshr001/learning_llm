0002R：从一个元素走到 Q、K、V

本补强只处理 0002 答卷暴露的两个关键缺口：把复杂 stride 推导收敛成直接索引映射，以及理解 projection 后的最后一维怎样拆成 Q/K/V heads。已经答对的 B/S/N/D 轴交换不从头重讲。

1. 进入条件与本节成果

可以直接使用：你已经会计算 D=H/N，知道 reshape 保持元素总数，也知道 transpose(1,2) 把 [B,S,N,D] 变成 [B,N,S,D]。

本节结束时，你要能在不展开 storage offset 的情况下完成一个元素的反向映射，并从 projection 输出宽度推出 Q、K、V 的数字 shape。

2. 先追踪一个具体元素

令 B=1（一条序列）、S=2（两个 token）、H=6（每个 token 六个特征）、N=2（两个 head）、D=3（每个 head 三个特征）。

x[0,0] = [0, 1, 2, 3, 4, 5]
x[0,1] = [6, 7, 8, 9,10,11]

token 下标 1:
  head 0 = [6,7,8]
  head 1 = [9,10,11]

现在看 heads[0,1,1,2]：batch 下标 0、head 下标 1、token 下标 1、head 内下标 2。它是上表中的 11，对应 x[0,1,5]。

hidden 下标 = head 下标 * D + head 内下标
            = 1 * 3 + 2
            = 5
heads[b,n,s,d] = x[b,s,n*D+d]

你原答卷中的 stride 展开不是无效工作，但它多绕了一层。这里问的是逻辑元素对应关系：batch 下标不变，token 下标不变，只把 n 和 d 合回 hidden 下标。

3. offset 18 为什么对应数值 18

torch.arange(24) 依次生成 0 到 23。连续 tensor 的 storage offset 0 放数值 0，offset 18 放数值 18。因此一旦算出 x[1,1,2] 的 offset 是 18，答案就是 18，不需要再减 1。数组长度 24 的最后一个下标才是 23；“长度减一”不能应用到每个元素的值。

4. projection 到底提供了什么

Projection 是第 0001 课已经通过的 Linear。输入最后一维经过不同的 Linear 后，Q、K、V 可以得到不同宽度的输出。这个输出宽度就是接下来要拆开的 H=N*D；这里的 H 指该 projection 的输出宽度，不要求 Q 与 K/V 使用相同的 head 数。

用具体数字：B=1、S=3、Q 有 Nq=2 个 head、K/V 有 Nkv=1 个 head，每个 head 都有 D=4 个特征。

张量projection 后reshape 后transpose 后
Q[1,3,8]，因为 2*4=8[1,3,2,4][1,2,3,4]
K[1,3,4]，因为 1*4=4[1,3,1,4][1,1,3,4]
V[1,3,4]，因为 1*4=4[1,3,1,4][1,1,3,4]
不要从原模型 hidden size 猜最终 head shape。本题已经给出 head 数和每 head 特征数；先算各 projection 的输出宽度 N*D，再执行与 0002 完全相同的 split。

5. 再确认 view 边界

transpose 在这里返回共享同一 storage 的 view，通常不搬数据。它改变 shape 与 stride 的对应关系，所以直接 view() 可能无法用目标 shape 解释现有 stride。contiguous() 按当前逻辑次序整理出连续 storage。reshape() 能共享时共享、不能共享时可复制，所以不要依赖它必然采用其中一种方式。
