0005R：不要把三类 shape 放进同一个抽屉

你已经证明 RMSNorm 与 gated FFN 的公式、代码和数值都能工作。本补强只处理一个闭卷缺口：区分归约统计量、可训练参数和运行 tensor 的 shape。

1. 三类对象先分类

令输入 x.shape=[B=2,S=3,H=4]。固定一个元素 output[b,s,h]：

对象shape索引作用
mean_square[B,S,1]=[2,3,1]mean_square[b,s,0]每个 token 一个缩放统计量。
RMSNorm weight[H]=[4]weight[h]每个 hidden 特征一个可训练 gamma。
output[B,S,H]=[2,3,4]output[b,s,h]每个 token、每个特征一个结果。
output[b,s,h]
= x[b,s,h]
  * rsqrt(mean_square[b,s,0] + eps)
  * weight[h]

mean_square 的最后一维 1 广播到 H；weight 缺少 B、S 两个前导维度，等价于从右对齐为 [1,1,H]，广播到所有 batch 和 token。前者是每 token 的统计量，后者是跨 token 共享的可训练参数。

2. Linear 构造、weight storage 与运行数据流

PyTorch 构造写作 nn.Linear(in_features, out_features)，但 weight 按 [out_features,in_features] 存储。记忆方法不是背字母，而是看一个输出怎样计算：

output[..., out_index]
= sum(input[..., in_index] * weight[out_index, in_index])

每一行 weight 产生一个输出，所以第一轴必须是输出数，第二轴必须是输入数。

具体令 H=8,I=20：

层构造weight storage运行 tensor
gateLinear(8,20)[20,8][B,S,8] -> [B,S,20]
upLinear(8,20)[20,8][B,S,8] -> [B,S,20]
downLinear(20,8)[8,20][B,S,20] -> [B,S,8]
检查法：weight 的第二维必须能与输入 tensor 的最后一维相乘；weight 的第一维就是输出 tensor 的最后一维。

3. 与你已通过的代码交叉验证

self.gate_proj = nn.Linear(hidden_size, intermediate_size)
# 构造参数: (H,I)
# weight:    [I,H]
# tensor:    [B,S,H] -> [B,S,I]

你的实现写对了数据流，但闭卷答案把构造参数顺序当成了 weight shape。本补强要求能把三者分别写出，而不是修改已经正确的 FFN 代码。
