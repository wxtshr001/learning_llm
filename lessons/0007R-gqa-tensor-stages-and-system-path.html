0007R：分清 GQA 的 Tensor 阶段，再把它接回 Decoder

这是一节约 30～40 分钟的针对性补强。0007 已经证明的 head 映射、causal attention 数值、代码实现和 Cache 主公式不再重复。

1. 进入条件与本节成果

可以直接使用：你已经能计算 D=H/Nq、执行 split/transpose/merge、解释 Nq/Nkv 连续分组，并实现 GQA attention。

本节必须补齐：raw projection、split tensor、逻辑展开 tensor 与 merge tensor 不是同一阶段；“宽度里含有 Nq*D”不等于“存在显式 head axis”；RoPE 和 KV Cache 只考系统位置，不考 RoPE 数学。

最终成果：面对一组新数字，你能完整写出每个阶段的 rank、shape、axis 含义，并从 hidden_states 一直追到 residual add。

2. 先固定所有字母

符号含义本节数字
BBatch size，一次并行处理的序列数2
SSequence length，每条序列的 token 数3
HHidden size，residual stream 中每个 token 的特征数8
NqNumber of query heads，Q head 数4
NkvNumber of key/value heads，K/V head 数2
DHead dimension，每个 head 的特征数2

这里 Nq*D=4*2=8=H，而 Nkv*D=2*2=4。这两个乘积直接决定 q/k/v projection 的输出宽度。

3. raw projection 只有三个 axis

hidden_states 是 rank 3（3 个 axis）的 tensor：

hidden_states [B,S,H] = [2,3,8]
axis 0: batch
axis 1: token position
axis 2: hidden feature

对它做三个不同的 Linear projection：

q_proj: Linear(H, Nq*D)  → q_raw [B,S,Nq*D]  = [2,3,8]
k_proj: Linear(H, Nkv*D) → k_raw [B,S,Nkv*D] = [2,3,4]
v_proj: Linear(H, Nkv*D) → v_raw [B,S,Nkv*D] = [2,3,4]

raw 表示 Linear 刚输出、还没把 head 拆成单独 axis。以 k_raw[1,2,3] 为例，三个索引分别是 batch 1、token 2、扁平特征 3。此时不能写 k_raw[b,kv_head,s,d]，因为它只有 3 个 axis。

用 C++ 连续数组类比：最后一段长度 4 的内存以后可以解释为 2×2，但在 reshape 前，当前 tensor 视图仍只是一个长度 4 的维度。

4. split 后才出现显式 head axis

先把最后一维拆成“head 数 × 每 head 特征数”，再把 head axis 转到 axis 1：

q_raw [2,3,8]
→ reshape [B,S,Nq,D] = [2,3,4,2]
→ transpose          = Q [B,Nq,S,D] = [2,4,3,2]

k_raw/v_raw [2,3,4]
→ reshape [B,S,Nkv,D] = [2,3,2,2]
→ transpose           = K/V [B,Nkv,S,D] = [2,2,3,2]

现在 Q/K/V 都是 rank 4。Q 的 axis 1 长度是 Nq=4；K/V 的 axis 1 长度是 Nkv=2。

逐元素位置映射仍沿用你已经通过的规则：

k_raw[b,s,n*D+d] ↔ K[b,n,s,d]

例如 Nkv=2,D=2：
k_raw[1,2,3] 中 3 = 1*2+1
所以它在 K 中是 K[1,1,2,1]

数值没有被计算或平均，只是用新的 axis 解释同一批元素。

5. 逻辑展开服务计算，持久 Cache 仍是 Nkv

Nq=4,Nkv=2 时，Q head 到 KV head 的映射是 [0,0,1,1]。为便于理解，可以把 K/V 逻辑展开：

K/V stored:  [B,Nkv,S,D] = [2,2,3,2]
K/V logical: [B,Nq,S,D]  = [2,4,3,2]

stored 表示请求生命周期中真正持久保存在 KV Cache 的状态；logical 表示每个 Q head 计算时看见的映射关系。生产 kernel 可以按组索引，不一定真的复制出 expanded tensor。

每个 Q head 都产生自己的 score 表：

scores/weights [B,Nq,Sq,Sk] = [2,4,3,3]
head_output    [B,Nq,S,D]   = [2,4,3,2]

Sq 是 query token 数，Sk 是 key token 数；本例是 full-sequence，所以两者都等于 3。

6. merge 后 Nq 进入宽度，不再是 axis

head_output [B,Nq,S,D] = [2,4,3,2]   # rank 4，axis 1 是 Nq
transpose              = [2,3,4,2]
merge/reshape          = [B,S,Nq*D] = [2,3,8]  # rank 3
o_proj output          = [B,S,H] = [2,3,8]      # rank 3

merge 后最后一维的宽度 8 是由 Nq*D 得到，但 shape 中没有一个独立维度等于 Nq=4。因此应说“宽度编码了所有 Q heads 的特征”，不能说“merge 的 head axis 是 Nq”。

tensor是否有显式 Nq head axis原因
Q split有[B,Nq,S,D] 的 axis 1
logical K/V有为每个 Q head 提供逻辑视图
scores/weights有[B,Nq,Sq,Sk] 的 axis 1
head_output有[B,Nq,S,D] 的 axis 1
merge没有rank 3，head 已折叠进最后一维
o_proj output没有rank 3，回到 residual stream 的 H

7. 为什么 concat/merge 不能换成平均

固定一个 token，设 4 个 head 每个只有 D=1 个输出：

head0=2, head1=4, head2=20, head3=40

concat/merge → [2,4,20,40]   # 4 个特征，保留每个 head 身份
average      → 16.5          # 只剩 1 个特征，来源不可恢复

o_proj 是可训练的 Linear。它可以为 2、4、20、40 分别学习不同权重，再组合为 H 维输出。如果先平均，许多不同 head 组合都可能变成同一个 16.5，后面的 Linear 无法恢复丢失的信息。

平均并不是“另一种 shape 写法”，而是额外做了一次不可逆计算，同时把输入宽度从 Nq*D 降成 D，不再匹配本模型的 o_proj: Linear(Nq*D,H)。

8. 把 GQA 接回完整生成链

Causal LM 的大链条是：

token ids → embedding → 多个 decoder layers
→ final RMSNorm → LM Head → vocabulary logits
→ 选择 next token → 下一次 decode

GQA 在每个 decoder layer 的 Attention 子层里，不直接产生 logits：

hidden_states ───────────────────────────────────────── residual ───┐
  │                                                               │
  └→ RMSNorm → q/k/v projections → split heads                    │
       → RoPE(Q,K) → update/read KV Cache                         │
       → GQA causal attention → merge heads → o_proj ─────────────┤
                                                                  ↓
                                                           residual add

RoPE 是 Rotary Position Embedding，中文常译旋转位置编码。本节只要求知道：它作用在 split 后的 Q 和 K 上，并位于 score 计算之前；旋转公式、角度和代码在 0008 才学习与验收。

KV Cache 是跨 decode step 保存的运行状态。K 经过所需的位置处理后与 V 一起写入/读取 Cache；Q 只用于当前 step，不持久缓存。GQA causal attention 使用当前 Q 与历史 K/V 计算，再把 head outputs 交给 merge 和 o_proj。

类别本子层中的对象生命周期
Parameter（训练参数）RMSNorm weight、q/k/v/o projection weights模型持久保存，多请求共享
Activation（本次计算中间值）Q、当前 scores/weights、head output、merge output随 forward/step 产生和释放
State（请求状态）未展开的 K/V Cache在同一生成请求的多个 decode steps 间保留

9. 容量比例与节省比例不要混写

如果其他因子相同，Cache 大小与 Nkv 成正比。设 MHA 的 Nq=Nkv=8，GQA 的 Nkv=2：

GQA/MHA 容量比例 = 2/8 = 25%
节省比例 = 1 - 25% = 75%

问“还剩多少”回答 25%；问“省了多少”回答 75%。
