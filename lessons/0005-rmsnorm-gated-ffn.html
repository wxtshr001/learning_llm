0005：每个 token 先归一化，再经过带门控的特征变换

本课实现 decoder 中两个不混合 token 位置的组件：RMSNorm 和 gated FFN。RMSNorm 调整每个 token 向量的整体尺度；gated FFN 用两个并行投影产生“门”和“内容”，逐元素相乘后再投影回 hidden size。

1. 符号与目标

符号英文含义
BBatch size一次处理的序列数量。
SSequence length每条序列中的 token 数。
HHidden size每个 token 的输入/输出特征数。
IIntermediate sizeFFN 内部扩展后的特征数。
εepsilon防止除零的很小正数，代码名通常是 eps。
γgammaRMSNorm 的逐特征可训练缩放参数，代码中叫 weight。

输入：x.shape=[B,S,H]。本节成果：实现 RMSNorm 和 gated FFN，保持输出 shape 为 [B,S,H]，并与 PyTorch/显式 reference 结果在容差内一致。

2. RMSNorm 先看一个具体向量

一个 token 的 hidden 向量为 x=[1,2,-1,-2]，所以 H=4。先暂时令 ε=0、γ=[1,1,1,1]：

平方:        [1, 4, 1, 4]
平方平均:    (1+4+1+4) / 4 = 2.5
RMS:         sqrt(2.5) ≈ 1.5811
归一化结果:  x / 1.5811
             ≈ [0.6325, 1.2649, -0.6325, -1.2649]

RMS 是 root mean square（均方根）：先平方、求平均、再开平方。一般公式：

rms(x) = sqrt(mean(x^2) + ε)
output = x / rms(x) * γ

乘法、除法和平方都对元素执行；mean 只沿最后一个 H 轴求平均。对于 [B,S,H]，每个 [H] token 向量各算自己的 rms，B 和 S 不互相混合。

RMSNorm 不减去均值；它只用平方均值控制向量尺度。shape 从头到尾保持 [B,S,H]。

3. PyTorch 实现与参数 shape

class TinyRMSNorm(nn.Module):
    def __init__(self, hidden_size, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))  # [H]
        self.eps = eps

    def forward(self, x):
        input_dtype = x.dtype
        variance = x.float().pow(2).mean(dim=-1, keepdim=True)
        normalized = x.float() * torch.rsqrt(variance + self.eps)
        return self.weight * normalized.to(input_dtype)

variance 在这里是平方平均值，shape 为 [B,S,1]；keepdim=True 保留最后一个长度为 1 的轴，使它能按广播规则除到 [B,S,H]。rsqrt(v) 表示 1/sqrt(v)。

中间转 float32 是常见的数值稳定做法，最后转回输入 dtype。weight 的 shape 是 [H]，会广播到每个 batch、每个 token。

4. 从普通 FFN 到 Gated FFN：结构、作用与逐步数据流

先不要急着看 gate_proj。必须先知道普通 FFN 在做什么。FFN 是 feed-forward network（前馈网络）：它对每个 token 的 hidden 向量独立做一次“升维 → 非线性变换 → 降维”。

4.1 普通 FFN 是什么

固定一个 token，输入是长度为 H 的向量 x[b,s,:]。普通 Transformer FFN 通常只有两个 Linear：

输入 x[B,S,H]
→
up projectionH → I
→
activation逐元素激活
→
down projectionI → H
→
输出 y[B,S,H]

图 1：普通 FFN 的结构图。I 是 intermediate size（中间特征数），通常比 H 大；它像在 C++ 中申请一块更宽的临时 feature buffer。类比只帮助理解 shape：实际 Linear 是矩阵运算，不是手工搬运数组。

ordinary_ffn(x) = down_proj( activation(up_proj(x)) )
步骤输入 → 输出做什么为什么需要
up_proj[B,S,H] → [B,S,I]把每个 token 从 H 个特征映射到 I 个中间特征。提供更宽的特征组合空间。
activation[B,S,I] → [B,S,I]逐元素加入非线性。如果连续两层都只有 Linear，它们可合并成一个 Linear，表达能力受限。
down_proj[B,S,I] → [B,S,H]把临时的 I 个特征重新组合回 H 个特征。恢复 decoder 主路径要求的 hidden size，才能与其他 [B,S,H] 结果相加或传给下一层。

4.2 SiLU 做了什么

SiLU 是 Sigmoid Linear Unit。它不是 Linear 层，而是对 tensor 中每个元素 z 独立计算：

sigmoid(z) = 1 / (1 + exp(-z))
SiLU(z) = z × sigmoid(z)

sigmoid(z) 给出一个 0 到 1 之间的缩放因子；再乘回 z。因此 SiLU 会让不同数值通过不同程度，而且不像 ReLU 那样把所有负数直接变成 0。

zsigmoid(z)SiLU(z)观察
-2约 0.1192约 -0.2384负值被压小，但没有强制清零。
00.50零仍然是零。
2约 0.8808约 1.7616较大的正值大部分通过。

4.3 Gated FFN 比普通 FFN 多了什么

普通 FFN 只有一条 H → I 路径。Gated FFN 把输入分成两条并行路径：

  • gate 路径：gate_proj 产生门控原始值，再经 SiLU 得到每个中间特征的调节系数。
  • up 路径：up_proj 产生要被调节的内容。
输入 x[B,S,H]
↗
↘
gate_projH → I
→
SiLU得到 gate
up_projH → I
→
up内容路径
→
逐元素相乘 ×gate * up
[B,S,I]
mixed[B,S,I]
→
down_projI → H
→
output[B,S,H]

图 2：Gated FFN 数据流。两条分支读取同一个 token 的 x，在相同的 I 轴上逐元素汇合；它们不会混合不同 token。

4.4 第一步：gate_proj 产生 gate_raw

gate_raw = gate_proj(x)     # [B,S,H] -> [B,S,I]

gate_proj 是一个从 H 到 I 的 Linear。它学习“看到当前 token 的 H 个输入特征后，I 个中间通道分别应该得到什么门控原始值”。输出叫 gate_raw，因为它还没有经过 SiLU。

4.5 第二步：SiLU 把 gate_raw 变成 gate

gate = SiLU(gate_raw)       # [B,S,I] -> [B,S,I]

SiLU 不改变 shape，只逐元素改变数值。这里的 gate 不是只能取 0 或 1 的硬开关：它可以接近 0、为正，也可以是较小的负数。因此更准确的理解是“对每个中间特征做输入相关的连续调节”。

4.6 第三步：up_proj 产生内容 up

up = up_proj(x)             # [B,S,H] -> [B,S,I]

up_proj 也是 H 到 I 的 Linear，但它有自己独立的 weight。它负责生成 I 个候选内容特征。名称中的 up 表示从 H 扩展到 I，不表示数值一定变大。

4.7 第四步：gate 与 up 逐元素形成 mixed

mixed = gate * up           # [B,S,I] * [B,S,I] -> [B,S,I]

这里的 * 是 Hadamard product（逐元素乘法）。对固定位置 [b,s,i]：

mixed[b,s,i] = gate[b,s,i] × up[b,s,i]

它不是矩阵乘法，因为目标不是把 I 个特征互相求和，而是让第 i 个 gate 调节第 i 个内容特征。两边必须具有相同的 [B,S,I] shape。

4.8 第五步：down_proj 回到 hidden size

output = down_proj(mixed)   # [B,S,I] -> [B,S,H]

down_proj 把 I 个已门控的中间特征重新组合成 H 个输出特征。若不投影回 H，输出就无法回到 decoder 的 [B,S,H] 主路径。

4.9 用一个 token 追踪完整数值

假设某个 token 经两个 H→I 投影后，I=3：

gate_raw = [-2.0000,  0.0000, 2.0000]
gate     = SiLU(gate_raw)
         = [-0.2384,  0.0000, 1.7616]
up       = [ 3.0000, -4.0000, 0.5000]
mixed    = gate * up
         = [-0.7152, -0.0000, 0.8808]

再令 H=2，为便于手算，给定 down_proj.weight（PyTorch shape 是 [H=2,I=3]）：

down_proj.weight = [[1.0, 0.0, -1.0],
                    [0.5, 1.0,  0.0]]

output[0] = 1.0*(-0.7152) + 0.0*0 + (-1.0)*0.8808 = -1.5960
output[1] = 0.5*(-0.7152) + 1.0*0 + 0.0*0.8808    = -0.3576
output    = [-1.5960, -0.3576]                    # [H=2]

4.10 相比普通 FFN，区别和提升在哪里

比较项普通 FFNGated FFN / SwiGLU
H→I 路径一条两条：gate 与 up
核心公式down(act(up(x)))down(SiLU(gate(x))*up(x))
中间特征控制只有 activation 改变单一路径gate 根据同一输入逐通道调节另一条内容路径
Linear 参数量
忽略 bias、使用相同 I		H*I + I*H = 2HIH*I + H*I + I*H = 3HI
代价较低相同 I 下，多一个 H→I 投影，参数量与主要矩阵计算约增加 50%

提升来自哪里：Gated FFN 不只是对一组中间值做固定形式的激活，而是让一条从输入计算出的 gate 路径逐通道调节另一条内容路径，提供更灵活的输入相关特征选择。GLU Variants Improve Transformer 报告，SwiGLU 等 GLU 变体在其 Transformer 实验中优于所比较的 ReLU/GELU FFN。

不要把论文结果理解成无条件保证。Gated FFN 在相同 H、I 下更贵；实际模型可能调整 I，使总参数量或计算预算更接近。具体收益还取决于模型规模、训练数据和训练设置。Qwen3 使用的正是 down_proj(SiLU(gate_proj(x))*up_proj(x)) 这条数据流。

5. Linear weight 的 shape 不要写反

PyTorch nn.Linear(in_features, out_features, bias=False) 的 weight shape 是 [out_features,in_features]：

层逻辑变换weight shape输出 shape
gate_projH → I[I,H][B,S,I]
up_projH → I[I,H][B,S,I]
down_projI → H[H,I][B,S,H]

这与前面课程使用的数学记号 X @ W 中 W 常写成 [in,out] 不同。PyTorch Linear 内部按其 API 存储为 [out,in]，等价计算会使用 weight 的转置关系。

6. 完整 Module

class GatedFFN(nn.Module):
    def __init__(self, hidden_size, intermediate_size):
        super().__init__()
        self.gate_proj = nn.Linear(hidden_size, intermediate_size, bias=False)
        self.up_proj = nn.Linear(hidden_size, intermediate_size, bias=False)
        self.down_proj = nn.Linear(intermediate_size, hidden_size, bias=False)

    def forward(self, x):
        gate = torch.nn.functional.silu(self.gate_proj(x))
        up = self.up_proj(x)
        return self.down_proj(gate * up)

三个 Linear 都会被父 Module 注册，它们的 weight 都是 Parameter。backward 会沿 down、逐元素乘法、SiLU、gate/up 两条路径计算梯度。

7. 它是否混合 token

RMSNorm 沿 H 轴处理每个 token；三个 Linear 也只变换最后一个特征轴。固定 b（batch 下标）和 s（token 下标）后，输出只依赖同一个 x[b,s,:]，不会读取另一个 token 的 x[b,s2,:]。token 之间的混合由 Attention 等组件完成，不是本课 FFN 的职责。

8. parity：不要只看“能运行”

parity 在本课程中表示参考实现与待测实现数值对齐。RMSNorm 与 nn.RMSNorm 使用相同 weight/eps；gated FFN 与显式 F.linear + F.silu + multiply 使用相同权重：

max_error = (reference - candidate).abs().max().item()
torch.testing.assert_close(reference, candidate, rtol=1e-5, atol=1e-6)

还要检查 shape、dtype、device、参数 shape，以及 backward 后所有 Parameter 的 grad 是否存在且为有限数。

9. 与真实 Qwen 的连接

Qwen 系列的 MLP 使用同样的结构：

down_proj( act_fn(gate_proj(x)) * up_proj(x) )

真实模型的 H、I 更大，dtype、kernel 和量化更复杂，但 shape 路径不变。第 0005 课建立的是以后阅读 Qwen MLP、对齐导出结果和定位 backend 数值问题的最小 reference。
