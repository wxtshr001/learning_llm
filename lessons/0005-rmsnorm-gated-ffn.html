0005：每个 token 先归一化，再经过带门控的特征变换

本课实现 decoder（逐步生成 token 的模型主体）中两个不混合 token 位置的组件：RMSNorm 和 gated FFN。RMSNorm 调整每个 token 向量的整体尺度；gated FFN 用两个并行投影产生“门”和“内容”，逐元素相乘后再投影回 hidden size。这里的 decoder 主路径可先理解为：各层之间持续传递 shape 为 [B,S,H] 的 hidden state（隐藏特征 tensor）。

2. RMSNorm：为什么做、怎样做、每一步改变什么

RMSNorm 是 Root Mean Square Normalization（均方根归一化）。先看它解决的直观问题：两个 token 向量可能方向相同，但整体数值尺度差很多。

x1 = [ 1,  2, -1, -2]
x2 = [10, 20,-10,-20] = 10 * x1

x2 的每个元素都是 x1 的 10 倍。暂时令 ε=0，RMSNorm 会分别计算它们的整体尺度并除掉，因此二者在“除以 RMS”后相同。这一步控制“整个 hidden 向量有多大”，同时保留各特征之间的相对比例和正负号；后面的可训练 γ 还可以继续逐特征调整。

x[H]
→
逐元素平方x²
→
求平方平均mean square
→
开平方RMS
→
x / RMS统一尺度
→
乘 γ逐特征缩放

2.1 用一个 token 完整手算

一个 token 的 hidden 向量为 x=[1,2,-1,-2]，所以 H=4。先令 ε=0、γ=[1,1,1,1]：

步骤 1，平方:      [1, 4, 1, 4]
步骤 2，平方平均:  (1+4+1+4) / H = 10/4 = 2.5
步骤 3，RMS:       sqrt(2.5) ≈ 1.5811
步骤 4，除以 RMS:  x / 1.5811
                   ≈ [0.6325, 1.2649, -0.6325, -1.2649]
步骤 5，乘 γ:      结果不变，因为此时 γ 全为 1

2.2 epsilon 和 gamma 各自做什么

若 x=[0,0,0,0]，RMS 也是 0，直接除会产生无效数值。ε（epsilon）是加入分母内部的小正数：

rms(x) = sqrt(mean(x²) + ε)
output[h] = x[h] / rms(x) × γ[h]

γ 是长度为 H 的可训练 weight。比如归一化结果前两个值为 [0.6325,1.2649]，而 γ 前两个值为 [2,0.5]，相乘后变成 [1.2650,0.6325]。因此 RMSNorm 先统一整体尺度，再允许模型为每个 hidden 特征学习不同缩放。

RMSNorm 不做什么：它不减去均值，也不混合不同 token。它与 LayerNorm 不是同一个公式。本课只要求 RMSNorm，不要求先掌握 LayerNorm。

3. RMSNorm 的 axis、广播、dtype 与 PyTorch 实现

3.1 从具体 [B=1,S=2,H=4] 看 reduction

x = [[[ 1.0,  2.0, -1.0, -2.0],
      [ 0.5, -0.5,  1.5, -1.5]]]
shape = [1,2,4]

mean(dim=-1) 是 reduction（归约）：把最后 H 轴的 4 个数汇总成 1 个数。每个 token 独立计算：

token 0 mean_square = (1 + 4 + 1 + 4) / 4 = 2.50
token 1 mean_square = (0.25 + 0.25 + 2.25 + 2.25) / 4 = 1.25

使用 keepdim=True 后，结果不是 [1,2]，而是 [1,2,1]：

mean_square = [[[2.50],
                [1.25]]]       # shape [B=1,S=2,1]

最后长度 1 会广播到 H=4。具体元素映射为：

normalized[b,s,h] = x[b,s,h] × rsqrt(mean_square[b,s,0] + eps)

例如 x[0,1,2]=1.5 使用的是同一个 token 的 mean_square[0,1,0]=1.25，不会使用 token 0 的 2.50。可把它类比为 C++ 两层外循环固定 b,s，先扫描 H 个连续元素求平方平均，再扫描同一段 H 元素归一化。

3.2 逐行读实现

class TinyRMSNorm(nn.Module):
    def __init__(self, hidden_size, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))  # gamma, [H]
        self.eps = eps                                       # 普通 Python float

    def forward(self, x):
        input_dtype = x.dtype
        x_float = x.float()                                  # 中间计算用 float32
        mean_square = x_float.pow(2).mean(dim=-1, keepdim=True)
        normalized = x_float * torch.rsqrt(mean_square + self.eps)
        scaled = normalized * self.weight.float()            # [B,S,H] * [H]
        return scaled.to(input_dtype)
代码含义shape
nn.Parameter(ones(H))注册可训练的 γ；会出现在 named_parameters()。[H]
pow(2)每个元素平方，不改变位置。[B,S,H]
mean(dim=-1,keepdim=True)每个 token 的 H 个平方值归约成 1 个数。[B,S,1]
rsqrt(v)计算 1/sqrt(v)，等价于“除以 RMS”所需的倒数。[B,S,1]
* weight[H] 广播到每个 batch、每个 token。[B,S,H]

eps 只是配置值，不是 Parameter。中间转 float32 是为了让平方、求和和倒数平方根更稳定；最后在所有乘法完成后转回 input_dtype，才严格保证返回 dtype 与输入一致。

变量应叫 mean_square（平方平均），而不是统计学上的 variance（方差）。RMSNorm 没有先减均值，所以这两者不能混称。

4. 从普通 FFN 到 Gated FFN：结构、作用与逐步数据流

先不要急着看 gate_proj。必须先知道普通 FFN 在做什么。FFN 是 feed-forward network（前馈网络）：它对每个 token 的 hidden 向量独立做一次“升维 → 非线性变换 → 降维”。

4.1 普通 FFN 是什么

固定一个 token，输入是长度为 H 的向量 x[b,s,:]。普通 Transformer FFN 通常只有两个 Linear：

输入 x[B,S,H]
→
up projectionH → I
→
activation逐元素激活
→
down projectionI → H
→
输出 y[B,S,H]

图 1：普通 FFN 的结构图。I 是 intermediate size（中间特征数），通常比 H 大；它像在 C++ 中申请一块更宽的临时 feature buffer。类比只帮助理解 shape：实际 Linear 是矩阵运算，不是手工搬运数组。

ordinary_ffn(x) = down_proj( activation(up_proj(x)) )
步骤输入 → 输出做什么为什么需要
up_proj[B,S,H] → [B,S,I]把每个 token 从 H 个特征映射到 I 个中间特征。提供更宽的特征组合空间。
activation[B,S,I] → [B,S,I]逐元素加入非线性。如果连续两层都只有 Linear，它们可合并成一个 Linear，表达能力受限。
down_proj[B,S,I] → [B,S,H]把临时的 I 个特征重新组合回 H 个特征。恢复 decoder 主路径要求的 hidden size，才能与其他 [B,S,H] 结果相加或传给下一层。

4.2 SiLU 做了什么

SiLU 是 Sigmoid Linear Unit。它不是 Linear 层，而是对 tensor 中每个元素 z 独立计算：

sigmoid(z) = 1 / (1 + exp(-z))
SiLU(z) = z × sigmoid(z)

sigmoid(z) 给出一个 0 到 1 之间的缩放因子；再乘回 z。因此 SiLU 会让不同数值通过不同程度，而且不像 ReLU 那样把所有负数直接变成 0。

zsigmoid(z)SiLU(z)观察
-2约 0.1192约 -0.2384负值被压小，但没有强制清零。
00.50零仍然是零。
2约 0.8808约 1.7616较大的正值大部分通过。

4.3 Gated FFN 比普通 FFN 多了什么

普通 FFN 只有一条 H → I 路径。Gated FFN 把输入分成两条并行路径：

  • gate 路径：gate_proj 产生门控原始值，再经 SiLU 得到每个中间特征的调节系数。
  • up 路径：up_proj 产生要被调节的内容。
输入 x[B,S,H]
↗
↘
gate_projH → I
→
SiLU得到 gate
up_projH → I
→
up内容路径
→
逐元素相乘 ×gate * up
[B,S,I]
mixed[B,S,I]
→
down_projI → H
→
output[B,S,H]

图 2：Gated FFN 数据流。两条分支读取同一个 token 的 x，在相同的 I 轴上逐元素汇合；它们不会混合不同 token。

4.4 第一步：gate_proj 产生 gate_raw

gate_raw = gate_proj(x)     # [B,S,H] -> [B,S,I]

gate_proj 是一个从 H 到 I 的 Linear。它学习“看到当前 token 的 H 个输入特征后，I 个中间通道分别应该得到什么门控原始值”。输出叫 gate_raw，因为它还没有经过 SiLU。

4.5 第二步：SiLU 把 gate_raw 变成 gate

gate = SiLU(gate_raw)       # [B,S,I] -> [B,S,I]

SiLU 不改变 shape，只逐元素改变数值。这里的 gate 不是只能取 0 或 1 的硬开关：它可以接近 0、为正，也可以是较小的负数。因此更准确的理解是“对每个中间特征做输入相关的连续调节”。

4.6 第三步：up_proj 产生内容 up

up = up_proj(x)             # [B,S,H] -> [B,S,I]

up_proj 也是 H 到 I 的 Linear，但它有自己独立的 weight。它负责生成 I 个候选内容特征。名称中的 up 表示从 H 扩展到 I，不表示数值一定变大。

4.7 第四步：gate 与 up 逐元素形成 mixed

mixed = gate * up           # [B,S,I] * [B,S,I] -> [B,S,I]

这里的 * 是 Hadamard product（逐元素乘法）。对固定位置 [b,s,i]：

mixed[b,s,i] = gate[b,s,i] × up[b,s,i]

它不是矩阵乘法，因为目标不是把 I 个特征互相求和，而是让第 i 个 gate 调节第 i 个内容特征。两边必须具有相同的 [B,S,I] shape。

4.8 第五步：down_proj 回到 hidden size

output = down_proj(mixed)   # [B,S,I] -> [B,S,H]

down_proj 把 I 个已门控的中间特征重新组合成 H 个输出特征。若不投影回 H，输出就无法回到 decoder 的 [B,S,H] 主路径。

4.9 用一个 token 追踪完整数值

假设某个 token 经两个 H→I 投影后，I=3：

gate_raw = [-2.0000,  0.0000, 2.0000]
gate     = SiLU(gate_raw)
         = [-0.2384,  0.0000, 1.7616]
up       = [ 3.0000, -4.0000, 0.5000]
mixed    = gate * up
         = [-0.7152, -0.0000, 0.8808]

再令 H=2，为便于手算，给定 down_proj.weight（PyTorch shape 是 [H=2,I=3]）：

down_proj.weight = [[1.0, 0.0, -1.0],
                    [0.5, 1.0,  0.0]]

output[0] = 1.0*(-0.7152) + 0.0*0 + (-1.0)*0.8808 = -1.5960
output[1] = 0.5*(-0.7152) + 1.0*0 + 0.0*0.8808    = -0.3576
output    = [-1.5960, -0.3576]                    # [H=2]

4.10 相比普通 FFN，区别和提升在哪里

比较项普通 FFNGated FFN / SwiGLU
H→I 路径一条两条：gate 与 up
核心公式down(act(up(x)))down(SiLU(gate(x))*up(x))
中间特征控制只有 activation 改变单一路径gate 根据同一输入逐通道调节另一条内容路径
Linear 参数量
忽略 bias、使用相同 I		H*I + I*H = 2HIH*I + H*I + I*H = 3HI
代价较低相同 I 下，多一个 H→I 投影，参数量与主要矩阵计算约增加 50%

提升来自哪里：Gated FFN 不只是对一组中间值做固定形式的激活，而是让一条从输入计算出的 gate 路径逐通道调节另一条内容路径，提供更灵活的输入相关特征选择。GLU Variants Improve Transformer 报告，SwiGLU 等 GLU 变体在其 Transformer 实验中优于所比较的 ReLU/GELU FFN。

不要把论文结果理解成无条件保证。Gated FFN 在相同 H、I 下更贵；实际模型可能调整 I，使总参数量或计算预算更接近。具体收益还取决于模型规模、训练数据和训练设置。Qwen3 使用的正是 down_proj(SiLU(gate_proj(x))*up_proj(x)) 这条数据流。

5. Linear weight 为什么是 [out,in]

PyTorch nn.Linear(in_features, out_features, bias=False) 把 weight 存成 [out_features,in_features]。先用 H=2,I=3 的 gate_proj 手算：

x = [4,5]                              # [H=2]
gate_proj.weight = [[1,0],             # 输出特征 0 使用的一整行
                    [0,2],             # 输出特征 1 使用的一整行
                    [3,1]]             # 输出特征 2 使用的一整行
shape = [I=3,H=2]

gate_raw[0] = 1*4 + 0*5 = 4
gate_raw[1] = 0*4 + 2*5 = 10
gate_raw[2] = 3*4 + 1*5 = 17
gate_raw = [4,10,17]                   # [I=3]
output[...,i] = Σh=0..H-1 input[...,h] × weight[i,h]

每一行 weight 产生一个输出特征，所以第一轴是 out，第二轴是 in。可类比 C++ 中一张连续的二维系数表：第 i 行保存“怎样从全部 H 个输入算出第 i 个输出”。PyTorch 内部等价于 x @ weight.T；这就是为什么你之前熟悉的数学 W 常写 [in,out]，而 Linear.weight 存成 [out,in]。

层构造weight shapetensor 数据流
gate_projLinear(H,I)[I,H][B,S,H] → [B,S,I]
up_projLinear(H,I)[I,H][B,S,H] → [B,S,I]
down_projLinear(I,H)[H,I][B,S,I] → [B,S,H]
不要从变量名猜 weight shape。始终先写 Linear(in_features,out_features)，再按 PyTorch 规则得到 weight=[out,in]。

6. 完整 Module：构造、注册、forward 与 backward

__init__ 负责创建长期存在的子模块和参数；forward 负责描述一次输入怎样流过这些子模块。调用 ffn(x) 时，nn.Module 会进入 forward(x)。

class GatedFFN(nn.Module):
    def __init__(self, hidden_size, intermediate_size):
        super().__init__()
        self.gate_proj = nn.Linear(hidden_size, intermediate_size, bias=False)
        self.up_proj = nn.Linear(hidden_size, intermediate_size, bias=False)
        self.down_proj = nn.Linear(intermediate_size, hidden_size, bias=False)

    def forward(self, x):
        gate = torch.nn.functional.silu(self.gate_proj(x))
        up = self.up_proj(x)
        return self.down_proj(gate * up)

up_proj.weight是up_proj.weight

hidden_size/intermediate_size否只是构造时使用的整数

bias=False 表示这三个 Linear 没有 bias Parameter，这是本课对齐 Qwen MLP 结构的选择，并不表示所有 Linear 都应该禁用 bias。

backward 从 loss 反向经过 down_proj 和逐元素乘法后分叉：一条到 up_proj，另一条经过 SiLU 到 gate_proj。因此只要 loss 依赖 output，三组 weight 都应得到 grad。梯度具体数值可能为 0，但 grad is None 表示根本没有建立到该参数的梯度路径。

7. 为什么 RMSNorm 和 FFN 不混合 token

“不混合 token”不是指整个 tensor 只含一个 token，而是指固定输出位置 [b,s,:] 后，它只读取同一个输入位置 x[b,s,:]。

组件读取范围是否读取另一个 s
RMSNorm固定 b、s，沿 H 轴读取 x[b,s,0:H]否
gate/up/down Linear固定 b、s，矩阵只作用于最后特征轴否
Attention一个 token 可根据规则读取其他 token 的信息是，这才承担 token mixing

用两个 token 做思想实验：

x[0,0,:] = [1,2,3,4]
x[0,1,:] = [5,6,7,8]

只把第二个 token 改成 [-5,-6,-7,-8]：
- RMSNorm/FFN 的 output[0,0,:] 应保持不变
- output[0,1,:] 会改变

索引层面的原因是公式始终保留相同的 b、s：

ffn_output[b,s,h_out] = Σi mixed[b,s,i] × down_weight[h_out,i]

求和发生在 I 轴，不发生在 S 轴。以后看到一个新算子时，可用同样方法检查：公式是否对 token 下标 s 求和，或读取了其他 s。

8. parity：怎样证明“实现正确”，而不只是“能运行”

parity 在这里表示 candidate（待测实现）与 reference（可信参考实现）在相同条件下数值对齐。脚本没有报异常，只能说明语法和某条执行路径可运行，不能证明公式写对。

同一输入
↗
↘
candidate
reference
→
比较 shape
→

→

  1. 相同输入：candidate 与 reference 接收同一个 x。
  2. 相同配置：RMSNorm 使用相同 eps；两个实现复制相同 weight。
  3. 先比结构：shape、dtype、device 必须符合契约。
  4. 再比数值：计算逐元素绝对误差和最大绝对误差。
  5. 最后测 backward：所有预期 Parameter 的 grad 都存在且为有限值。
difference = (reference - candidate).abs()
max_error = difference.max().item()
torch.testing.assert_close(reference, candidate,
                           rtol=1e-5, atol=1e-6)

你在 0003 已经使用过容差。这里复用同一规则：对每个 reference 元素，允许误差大致为 atol + rtol*abs(reference)。atol 是接近 0 时仍允许的绝对误差，rtol 随参考值大小缩放。

必须复制相同 weight。两个随机初始化的数学结构即使都正确，输出也通常不同；那是在比较参数，不是在比较实现。

9. 怎样把本课代码映射到真实 Qwen

模型源码常把 FFN 类命名为 MLP（multi-layer perceptron，多层感知机）。在 Qwen3 的 MLP 中，本课每个对象都有直接对应：

本课Qwen3 源码中的角色不变的核心含义
TinyRMSNorm.weightRMSNorm weight沿最后 H 轴归一化后逐特征缩放
gate_projself.gate_projH→I 的 gate 路径
F.silu配置选择的 act_fnQwen 常用 SiLU/SwiGLU 门控激活
up_projself.up_projH→I 的内容路径
down_projself.down_projI→H 返回 decoder 主路径
# 本课与 Qwen3 MLP 的共同核心
down_proj( act_fn(gate_proj(x)) * up_proj(x) )

真实模型的 H、I、层数和 dtype 更大，还会遇到 quantization（量化，用更低位数表示 weight/activation）、fused kernel（融合算子，把多步计算合成一次底层执行）和 export graph（提前导出的计算图）；但这些工程变化不能改变本节的 shape 和元素关系。以后若移动端输出不一致，可按本课边界逐段定位：

  1. RMSNorm 输出是否对齐；
  2. gate_proj/up_proj 是否各自对齐；
  3. SiLU 与逐元素乘法是否对齐；
  4. down_proj 是否对齐。

这就是本课与最终 On-device LLM Systems 目标的连接：先建立可解释的最小 reference，之后才能判断错误来自模型公式、export lowering（把高层图算子转换成目标 runtime 支持的低层算子）、量化，还是 runtime kernel（在设备上真正执行算子的底层实现）。
