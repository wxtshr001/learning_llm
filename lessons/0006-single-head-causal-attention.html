0006：从 Transformer 数据流理解单头 Causal Attention

本课不把 Attention 当成孤立公式。先看它在 Transformer decoder（逐 token 生成文本的模型主体）中的位置，再从一个 token 怎样选择并读取过去信息开始，逐步得到 Q、K、V、score、scale、causal mask、softmax 和 value 加权。

1. 这节课在整个 Transformer inference 模块中的位置

Transformer 是由许多 decoder layer（解码器层）重复堆叠起来的网络。inference 是使用训练好的参数执行输入到输出的计算，不在本课更新参数。文本进入模型后的主路径是：

token ids
   ↓ token embedding：把整数 token id 查表变成 H 维向量
hidden_states [B,S,H]
   ↓ 重复经过 L 个 decoder layer
final hidden_states [B,S,H]
   ↓ final RMSNorm
   ↓ LM Head：H 维向量映射为词表 VocabSize 个 logits
next-token logits [B,S,VocabSize]
   ↓ 选择下一个 token，再继续生成

这里 B 是 batch size（同时处理的序列数），S 是 sequence length（每条序列已有的 token 数），H 是 hidden size（每个 token 在层间主路径上的特征数），L 是 decoder layer 数。

一个常见的 pre-norm decoder layer 数据流如下。pre-norm 指每个主要子层之前先做归一化：

                         ┌──────── residual 1 ────────┐
hidden_states [B,S,H] ──┼→ RMSNorm → Self-Attention ├→ add → h [B,S,H]
                         └────────────────────────────┘
                                                    ┌──── residual 2 ────┐
                               h [B,S,H] ───────────┼→ RMSNorm → FFN/MLP ├→ add → layer output
                                                    └────────────────────┘
组件在 layer 中做什么是否主动混合 token
RMSNorm（0005）逐 token 调整 H 个特征的尺度，为下一个子层准备输入否
Self-Attention（本课起）让位置 q 从允许的 token 位置汇集信息是，这是 decoder layer 的跨 token 通信阶段
Residual add把子层计算出的改变量加回原 hidden state它只做同位置相加
Gated FFN / MLP（0005）逐 token 进一步变换已经汇集好的特征否，但输入已经含 Attention 汇集的上下文
本课的边界：只把 Self-Attention 内核缩小为一组 Q/K/V（single head，单头）来学清计算。真实模型还会有 Q/K/V Linear projection、多个 head、output projection、RoPE、KV Cache 等；它们的位置会在本课说明，但其独立实现分别在 0007、0008、0010 验收。

模块 B 各课怎样装回同一条 Transformer 数据流

课次加入的部件在整体中的作用

0007MHA / GQA并行使用多组 attention 子空间，并减少 K/V head 数以节省 Cache
0008RoPE把位置信息写入 Q/K，使 score 能反映相对位置
0009Tiny Decoder Layer把 RMSNorm、Attention、FFN 和两条 residual 真正组装起来
0010Prefill / decode / KV Cache复用过去的 K/V，避免每生成一个 token 都重算全部历史
0011Tiny Causal LM加 embedding、最终 norm、LM Head 和生成循环，形成可生成 token 的小模型

2. 先补上课程表没有直接写出的 Transformer 心智模型

下面这些不是额外背诵点，而是理解后续每个算子的坐标系。没有它们，Attention、RoPE、KV Cache 和 export 会变成四块互不相连的代码。

2.1 本模块实现的是 decoder-only Causal LM

LM 是 Language Model（语言模型）；Causal LM 按从左到右的条件概率预测下一个 token。对 token 序列 t0,t1,t2，模型学习的是：

P(t0,t1,t2) = P(t0) * P(t1 | t0) * P(t2 | t0,t1)

所以位置 2 可以使用位置 0、1、2 的输入表示，位置 1 不能使用位置 2。causal mask 不是随手加的优化，而是模型概率定义在 tensor 计算中的落实。

Transformer 还有 encoder-only、encoder-decoder 等结构；它们可能使用双向 self-attention 或 cross-attention（Q 来自一个序列、K/V 来自另一个序列）。本项目目标是 Qwen 类 decoder-only 模型，本课只讲同一 hidden sequence 产生 Q/K/V 的 causal self-attention。

2.2 Token、embedding、hidden state 和 logits 不是同一种东西

对象例子 shape含义
token ids[B,S]，整数分词器给出的词表编号，不含 H 维特征
embedding / hidden states[B,S,H]，浮点数每个 token 在模型内部的 H 维表示；经过每层后含义不断更新
Q/K/V单头先看 [B,S,D]由当前层 hidden states 临时投影出的匹配/内容表示
logits[B,S,VocabSize]每个词表 token 的未归一化下一个-token 分数

Attention 不直接读字符串，也不直接输出 token id。它只把 hidden vectors 变成新的 hidden vectors；经过所有层和 LM Head 后才得到词表 logits。

2.3 Residual stream 是贯穿所有层的主干

可以把 hidden_states [B,S,H] 看成一条 residual stream（残差主干）：每个 Attention 或 FFN 子层都根据当前主干计算一个 [B,S,H] 改变量，再加回主干。它不是程序中的全局变量，而是层与层之间持续传递的运行 tensor。

主干新值 = 主干旧值 + Attention 产生的改变量
主干再新值 = 主干新值 + FFN 产生的改变量

这解释了为什么 Attention 最终必须通过合并 heads 和 o_proj 回到 H：只有 shape 恢复为 [B,S,H] 才能与 residual 相加。某一层的 Attention 把过去信息写进位置 q 的 hidden vector；后面的 FFN 虽不跨 token，也能加工这份已经汇入的上下文；再下一层 Attention 可继续重组它。

2.4 参数、激活与 Cache 要分开

类别生命周期例子
Parameter（参数）训练学得；推理时跨请求反复使用q/k/v/o projection weight、RMSNorm weight、FFN weight
Activation（激活/运行 tensor）某次 forward 临时产生hidden_states、Q、scores、weights、Attention output
KV Cache（键值缓存）某次生成请求内跨 decode step 保留各 layer 已处理历史 token 的 K 和 V

KV Cache 不是模型参数，也不是把 attention weights 缓存下来。后续生成新 token 时，新 Q 仍需与历史 K 算 score，再用新 weights 读取历史 V。

2.5 同一模型有三种重要执行视角

视角输入长度Attention 做什么
训练/full-sequence一次输入整段 S并行算所有 q×k，再用 causal mask 防止未来泄漏
Prefill推理时一次处理整个 prompt得到 prompt 各位置表示，并为每层建立历史 K/V Cache
Decode step通常一次只输入新 token，query length=1新 Q 读取 Cache 中所有历史 K/V，再把新 K/V 追加到 Cache

本课先用 full-sequence 的方形 scores [B,S,S] 建立概念。到 0010 时 query length 可能是 1，而 key length 是累计历史长度，此时 scores 会是 [B,1,S_total]；“softmax 沿 key axis”仍然不变。这是公式跨执行形态保持稳定的核心。

2.6 Causal mask 与 padding mask 解决不同问题

  • Causal mask：按时间方向禁止 k>q，防止看未来；由位置关系决定。
  • Padding mask：批处理不同长度序列时，禁止读取补齐用的 PAD 位置；由每条样本的有效长度决定。

二者最终都可能把某些 score 设为极小值，但语义不同。本课代码只实现 causal mask，不能据此假设真实批处理不需要 padding 处理。

2.7 Attention 是动态路由，不是完整的模型记忆

Attention weights 会随输入和 query 改变，因此更像一次 forward 中动态计算的读取路由。模型长期知识主要编码在训练得到的参数中；当前请求的历史信息存在各层 hidden computation 和推理时的 KV Cache 中。把 Attention 简称为“记忆”会掩盖参数、激活和 Cache 的边界。

贯穿后续课程的四个问题：任何新组件都要回答：输入来自哪里？它沿哪个 axis 读写哪些位置？输出交给谁并怎样回到 residual stream？full-sequence、prefill 和 decode 时 shape/状态有什么变化？

3. 进入条件、必须从零解释的内容与成果

可以依赖：你已通过 rank/shape/axis、[B,S,H]、Linear、transpose、RMSNorm、FFN，以及参数 tensor 和运行 tensor 的区别。
不能依赖：你尚未证明 Q/K/V 的角色、score、sqrt(D) scale、causal mask、softmax key axis 和 value 加权；本课全部从零建立。

本课运行时直接接收 Q、K、V，以便只研究 Attention 内核。三者都是 rank 3 tensor：

tensorshape三个 axis
Q / K / V[B,S,D]axis 0=batch；axis 1=token position；axis 2=head 内的 feature

D 是 head dimension（当前这个 attention head 的特征数）。本课成果是亲手得到 score/weights [B,S_query,S_key]、output [B,S,D]，并用测试证明未来 token 不能影响过去输出。

4. Q、K、V 从哪里来，为什么要分成三种角色

Self-Attention 中的 self 表示 Q、K、V 都来自同一批输入 hidden states，而不是说三者数值相同。真实 decoder 会用三组不同的 Linear 参数：

x = input_rmsnorm(hidden_states)  # [B,S,H]
Q = q_proj(x)                    # [B,S,D]，本课单头简化
K = k_proj(x)                    # [B,S,D]
V = v_proj(x)                    # [B,S,D]

同一个 token 的向量 x[b,s,:] 经过三套不同权重，得到三种用途不同的表示：

名称英文与角色它参与哪一步
QQuery，当前位置 q 发出的“我要按哪些特征寻找信息”的匹配向量Q[q] 与所有允许的 K[k] 比较
KKey，位置 k 提供的“我适合被怎样匹配”的索引向量与 Q 点积，产生读取强度 score
VValue，位置 k 真正可被读走并汇入输出的内容向量由 softmax 权重加权求和

可以把它暂时类比为 C++ 中“先按索引计算权重，再用权重读取 payload”：Q/K 用来算地址相关性，V 是 payload。但边界必须说清：Q 不是自然语言问题，K 不是哈希表字符串键，V 也不是原 token；它们都是模型学习出的浮点向量，而且是连续的软匹配。

最重要的分工：Q 和 K 决定“从每个位置读多少”；V 决定“从那个位置读到什么”。改变 V 不会改变 attention weights；改变 Q 或 K 通常会改变 weights。

5. Score：固定一个 query，逐个 key 做点积

score 是匹配分数。先不用矩阵乘法，手算 D=2。固定 query 位置 q=1：

Q[1] = [1, 2]
K[0] = [1, 0]
K[1] = [0, 1]
K[2] = [1, 1]

未缩放 dot score(q=1,k=0) = 1*1 + 2*0 = 1
未缩放 dot score(q=1,k=1) = 1*0 + 2*1 = 2
未缩放 dot score(q=1,k=2) = 1*1 + 2*1 = 3

点积对 feature axis 的两个元素相乘后求和。它把两个长度 D 的向量变成一个标量。对所有 q、k 都这样算，就得到一个二维 score 表；加上 batch 后是 rank 3：

Q:                    [B,S_query,D]
K:                    [B,S_key,D]
K.transpose(-2,-1):  [B,D,S_key]
Q @ K^T:             [B,S_query,S_key]

例如 Q、K 都是 [2,5,4]：batch 2 保留；中间的 D=4 被矩阵乘法求和；留下 5 个 query 行和 5 个 key 列，所以 scores 是 [2,5,5]。

raw_score[b,q,k] = Σ(d=0..D-1) Q[b,q,d] * K[b,k,d]

q 是 score 表的行，k 是列。Q @ K.transpose(-2,-1) 只是把上述循环批量执行，不会把 Q、K、V 拼在一起。

6. Scale：为什么 score 要除以 sqrt(D)

scale 是缩放。raw score 是 D 项乘积的和。若各项大小相近且有正有负，D 增大时这个和的典型波动会增大；在常见独立、零均值的直觉假设下，方差随 D 增长，标准差约随 sqrt(D) 增长。因此使用：

score[b,q,k] = raw_score[b,q,k] / sqrt(D)

这不是为了改变 shape，而是控制送入 softmax 的数值尺度。若 score 差距过大，softmax 容易极端接近 0 或 1，其他位置几乎没有权重，训练时梯度也容易变得很小。

继续上一节 D=2 的数值：sqrt(2)≈1.414，缩放后的 q=1 行约为 [0.707,1.414,2.121]。三个元素仍对应三个 key，shape 没变。

不能除以 sqrt(S)：D 是每个点积累加的项数；S 是有多少个 key。点积的数值尺度由 D 决定，而不是由序列长度决定。

7. Causal mask：为什么 decoder 必须遮住未来

causal 表示输出位置 q 只依赖位置 k<=q。训练时整段序列可以并行送入模型，但预测位置 q 时不能偷看 q 后面的正确 token，否则训练与逐 token 生成的条件不一致。

mask 是标记哪些 score 禁止参与后续计算的布尔 tensor。对于 S=4，行是 query q，列是 key k：

future_mask[q,k]（True=禁止，False=允许）
          k0     k1     k2     k3
q0      False   True   True   True
q1      False  False   True   True
q2      False  False  False   True
q3      False  False  False  False

规则：k > q 的主对角线上方为 True；k <= q 为 False。

PyTorch 的 torch.triu(..., diagonal=1) 取主对角线上方。随后 masked_fill(mask, -inf) 把未来 score 换成负无穷：

future_mask = torch.triu(torch.ones(S, S, dtype=torch.bool), diagonal=1)
masked_scores = scores.masked_fill(future_mask, float("-inf"))

[S,S] mask 广播到每个 batch 的 [B,S,S] scores。mask 必须在 softmax 前应用，因为 exp(-inf)=0，被禁止位置才能在归一化时获得严格为 0 的权重。

8. Softmax：对固定 query 的所有 key 做归一化

softmax 把一行任意实数 score 转成非负、总和为 1 的权重。固定 batch b 和 query q，对 key 轴计算：

weights[b,q,k] = exp(masked_score[b,q,k])
                 / Σ(j=0..S_key-1) exp(masked_score[b,q,j])

分母中的 j 遍历这一行的所有 key。它不是沿 D 轴，因为 scores 里 D 已经在点积阶段被求和消失；也不是沿 query 轴，因为每个 query 都需要自己独立的一组“读取哪些 key”的权重。

小例子：一行允许的 score 是 [0,1]：

exp(0)=1，exp(1)≈2.718
总和≈3.718
weights≈[1/3.718, 2.718/3.718]≈[0.269,0.731]

若第三个未来 score 已变成 -inf，其指数为 0，所以 [0,1,-inf] 得到约 [0.269,0.731,0]。代码使用 F.softmax(masked_scores, dim=-1)；dim=-1 是最后一个 axis，即 key axis。

数值实现通常会先从一行所有 score 中减去该行最大值再取指数，以避免指数溢出；每个 score 同减一个常数不会改变 softmax 结果。PyTorch 的实现负责这种数值处理。

9. Value 加权：weights 决定读多少，V 提供内容

固定 query q 后，我们已有一行权重。现在沿 key 轴对 V 做加权和。假设某行：

weights[q] = [0.25, 0.75]
V[0] = [2, 4]
V[1] = [6, 8]

output[q, feature 0] = 0.25*2 + 0.75*6 = 5
output[q, feature 1] = 0.25*4 + 0.75*8 = 7
所以 output[q] = [5,7]

每个 output feature 都使用同一行 attention weights，但读取 V 中对应的 feature。逐元素公式是：

output[b,q,d] = Σ(k=0..S_key-1) weights[b,q,k] * V[b,k,d]

这里求和轴是 key position k，留下 b、q、d，所以：

weights: [B,S_query,S_key]
V:       [B,S_key,D]
output:  [B,S_query,D]
score 阶段对 feature d 求和，得到 q×k 的关系表；output 阶段对 key k 求和，把多个位置的 V 内容汇成每个 q 的一个 D 维向量。这是两个不同的求和轴。

10. 把完整链条用 D=1 精确走一遍

现在再看最容易手算的 B=1,S=3,D=1。Q/K 全为 1，V 依次为 1、3、5：

Q = [[1], [1], [1]]
K = [[1], [1], [1]]
V = [[1], [3], [5]]
  1. score：每对 Q/K 点积都是 1*1=1。
  2. scale：sqrt(D)=sqrt(1)=1，除完仍为 1。
  3. mask：每行未来列变成 -inf。
  4. softmax key axis：允许位置的 score 相等，因此允许的 key 平分总权重 1。
  5. 加权 V：每个 q 对允许的 V 求加权和。
masked scores                 weights                  output
q0 [1,-inf,-inf]       →     [1,0,0]          →       1*1 = 1
q1 [1,1,-inf]          →     [1/2,1/2,0]      →       1/2*1 + 1/2*3 = 2
q2 [1,1,1]             →     [1/3,1/3,1/3]    →       1/3*1 + 1/3*3 + 1/3*5 = 3

注意：均匀不是 Attention 永远如此，而是这个特制例子中所有允许 score 恰好相等。一般情况下 Q/K 不同，softmax 权重也不同。

11. 改 Q、K、V 分别会影响什么

修改直接影响 score/weights 的范围因果边界
Q[:,q,:]scores 的第 q 行：这个 query 对各 key 的匹配仍不能越过 mask 读取未来
K[:,k,:]scores 的第 k 列：所有能看到位置 k 的 query 对它的匹配只有 q>=k 的行可能受影响
V[:,k,:]不改变 scores 或 weights；改变读取到的内容只有对位置 k 权重非零的 q>=k 输出可能改变

因此，只改 V[:,2,:] 时，q=0、1 的输出必须完全不变，q=2 可能变化。这是因果行为测试，不只是 shape 测试。

12. Attention 输出怎样回到 Transformer 主路径

真实多头实现中，各 head 的输出会合并回 H 个特征，再经过 o_proj（output projection，输出线性投影）产生 Attention 子层的改变量：

normed = input_rmsnorm(hidden_states)        # [B,S,H]
Q, K, V = q_proj(normed), k_proj(normed), v_proj(normed)
head_context = causal_attention(Q, K, V)     # 本课研究的内核
attention_delta = o_proj(merge_heads(...))   # [B,S,H]
h = hidden_states + attention_delta          # residual 1

normed2 = post_attention_rmsnorm(h)
ffn_delta = gated_ffn(normed2)                # [B,S,H]
layer_output = h + ffn_delta                  # residual 2

本课函数输出的是单头 [B,S,D] context，还不是完整 decoder layer。0007 会解释多个 head 如何组合；0009 才要求把两条 residual 和 FFN 组装成 layer。这里先看全图，是为了知道每一步服务于哪里，而不是提前考后续实现。

13. PyTorch 代码与数学逐行对应

D = query.shape[-1]
# Q [B,S,D] @ K^T [B,D,S]，对 D 求和
scores = query @ key.transpose(-2, -1) / math.sqrt(D)

# [S,S]，主对角线上方 True 表示未来 key 禁止
future_mask = torch.triu(
    torch.ones(S, S, dtype=torch.bool, device=query.device), diagonal=1
)
masked_scores = scores.masked_fill(future_mask, float("-inf"))

# 固定 b、q，沿最后的 key axis 归一化
weights = F.softmax(masked_scores, dim=-1)

# [B,S_query,S_key] @ [B,S_key,D]，对 key 求和
output = weights @ value

推荐按执行顺序打印并检查：Q/K/V shape → raw scores → future mask → masked scores → weights → 每行权重和 → output。这样某一步错误时能定位，而不是只看最后结果。

14. 常见错误以及为什么错

错误后果
key 不 transpose最后两个矩阵轴无法按 D 配对，或得到错误语义
softmax 沿 query axis变成“固定 key 在多个 query 间分配”，不是每个 query 选择 key
mask 在 softmax 后才清零允许位置的剩余权重和小于 1；不是正确归一化分布
把主对角线也 mask位置 q 连自己都不能读取；q=0 会没有任何合法 key
除以 sqrt(S)混淆“点积累加项数 D”和“key 数量 S”
weights * V 直接逐元素乘[B,S,S] 与 [B,S,D] 的轴语义不同；需要矩阵乘法沿 key 求和
只检查 output shapemask 方向、softmax axis 或数值都可能错但 shape 仍正确
