0009：把已学组件组装成 Tiny Decoder Layer

本课唯一新增能力：不再孤立看 RMSNorm、Attention、RoPE 和 FFN，而是按正确顺序接成一个可堆叠 decoder layer，并追踪两次 residual add。

0. 系统坐标：一个 layer 在整台“机器”的哪里

token ids
  → embedding
  → decoder layer 0
  → decoder layer 1
  → ...
  → final RMSNorm
  → LM Head
  → logits
  → next token

本课只实现上图中的一个 decoder layer。输入是 hidden_states [B,S,H]，输出仍是 [B,S,H]，这样多个 layer 才能首尾相接。

本例满足 H=Nq*D=2*2=4。

1. residual stream 是贯穿所有 layer 的主干

把 hidden_states 想成一条宽度固定为 H 的主干数据总线。Attention 和 FFN 是两条支路：它们读取主干，计算一个“修正量”，再加回主干。

主干 x ────────────────┐
       → 子层计算 → delta ├→ x + delta
                        ┘

具体数字：若某 token 的主干为 x=[2,0,1,3]，Attention 支路输出 [0.1,0.2,-0.1,0]，第一次 residual 后：

x1 = [2,0,1,3] + [0.1,0.2,-0.1,0]
   = [2.1,0.2,0.9,3.0]

这是逐元素相加，所以两边必须同为 H 个特征。支路不能把 [B,S,I] 直接加回 [B,S,H]。

2. pre-norm 到底是什么意思

pre 表示“在子层之前”。pre-norm layer 先把主干的副本送进 RMSNorm，再把子层结果加回未归一化的 residual：

residual_0 = x0
attention_input = input_norm(x0)
attention_output = self_attn(attention_input)
x1 = residual_0 + attention_output
RMSNorm 的输出进入 Attention；residual 加法左边保存的是原始 x0。不能把公式误写成 norm(x0)+attention_output。

3. 第一条支路：RMSNorm → GQA Attention → residual

x0 [1,3,4]
 → input_norm                 [1,3,4]
 → q_raw                     [1,3,4]
   k_raw / v_raw             [1,3,2]
 → Q [1,2,3,2]
   K [1,1,3,2]
   V [1,1,3,2]
 → RoPE(Q,K)
 → causal GQA weights         [1,2,3,3]
 → head output               [1,2,3,2]
 → merge                     [1,3,4]
 → o_proj                    [1,3,4]  = attention_output
 → x1 = x0 + attention_output [1,3,4]

为什么需要 o_proj？Attention 内部用显式 heads 工作；residual stream 只接受 H 宽度。merge 把 Nq*D 扁平为 H，本课 H 恰好等于 Nq*D，再由 o_proj 学习组合各 head 特征。

4. 第二条支路不是从 x0 重新开始

residual_1 = x1
ffn_input = post_attention_norm(x1)
ffn_output = mlp(ffn_input)
x2 = residual_1 + ffn_output

这里的输入是已经包含 Attention 更新的 x1。如果写成 x0 + ffn_output，第一次 residual 加入的 Attention 信息就被绕开了。

两个 RMSNorm 是两个不同 module：

  • input_norm 服务 Attention 支路，拥有自己的 weight [H]。
  • post_attention_norm 服务 FFN 支路，也拥有独立的 weight [H]。

5. FFN 为什么先到 I，再必须回到 H

ffn_input [1,3,4]
 → gate_proj / up_proj        [1,3,6]
 → silu(gate) * up = mixed    [1,3,6]
 → down_proj                  [1,3,4] = ffn_output
 → x2 = x1 + ffn_output       [1,3,4]

I=6 是 FFN 内部临时工作宽度。down_proj 把 I 压回 H，才能和 x1 逐元素相加。

6. 用一个 token 看两次相加

引导脚本固定权重后，token 1 的实际输出为：

x0                  = [2.0000, 0.0000, 1.0000, 3.0000]
attention branch    = [0.0018, 0.0046, 0.0073, 0.0101]
x1                  = [2.0018, 0.0046, 1.0073, 3.0101]
ffn branch          = [0.0003, 0.0008, 0.0012, 0.0016]
x2 / layer_output   = [2.0022, 0.0053, 1.0085, 3.0116]

不要背这些小数。你需要看清：第二条支路读取 x1，最后也加回 x1。

7. 哪一步会混合 token

步骤跨 token 读取？原因
RMSNorm否每个 token 只在自己的 H axis 求均方
Q/K/V Linear、RoPE否逐 token 投影或旋转
causal Attention是query position 汇集允许看到的多个 K/V positions
Gated FFN否每个 token 独立做 H→I→H
residual add否同一位置同一 feature 相加

因此只修改未来 token 2，位置 0、1 的完整 layer 输出必须不变；修改 token 0，则后面位置可能因 Attention 读取历史而改变。

8. 完整 PyTorch 骨架

def forward(self, hidden_states, position_ids):
    residual_0 = hidden_states
    attention_input = self.input_norm(hidden_states)
    attention_output = self.self_attn(attention_input, position_ids)
    hidden_after_attention = residual_0 + attention_output

    residual_1 = hidden_after_attention
    ffn_input = self.post_attention_norm(hidden_after_attention)
    ffn_output = self.mlp(ffn_input)
    return residual_1 + ffn_output

residual_0 和 residual_1 只是 Python tensor 引用，不是 Parameter，也不是跨请求保存的 Cache state。

类别对象

Activationnorm 输出、Q/K/V、cos/sin、scores/weights、branch 输出、x1、x2
0009 请求 state无；本课是一次 full-sequence forward
0010 才加入的 state跨 decode steps 保存的历史 K_rope 与 V Cache

10. full-sequence、prefill、decode 的边界

  • full-sequence / prefill：本课一次输入 S 个 token，所有中间 activation 都带 S。
  • 单步 decode：当前输入通常 S=1，但 Attention 还要读取历史 Cache；本课尚未实现。
  • shape 不等于生命周期：当前 K/V 是一次 forward 的 activation；到 0010 被 Cache 保存后才成为请求 state。

11. 三个最有用的测试不变量

  1. shape：layer 输入输出都为 [B,S,H]。
  2. identity：把 Attention 的 o_proj 和 FFN 的 down_proj 置零，两条支路都输出零，layer 应原样返回输入。
  3. causal：只改未来 token，不得改变更早位置输出。
