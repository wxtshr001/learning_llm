reshape、transpose 与 Head Layout

Linear 把每个 token 投影为一条长向量；Attention 需要把它拆成多个 head。今天建立从元素索引到内存布局的完整映射。

本课成果：使用 PyTorch 完成 `[B,S,H] → [B,N,S,D] → [B,S,H]` 可逆变换；解释每个轴、元素映射、stride 与 contiguous 边界。

2. hidden 不是凭空变成 heads

[B,S,H]
H = N × D
↓ reshape
[B,S,N,D]
↓ transpose(1,2)
[B,N,S,D]

reshape 只把原来 hidden 轴中的连续区间重新解释为“第几个 head”和“head 内第几个特征”。元素映射为：

heads[b,n,s,d] = projected[b,s,n*D+d]

B、S 的长度不变；H 被拆成 N×D；transpose 只交换 S 与 N 的位置，任何轴长度都没有被数值改变。

3. 为什么 Attention 使用 [B,N,S,D]

对每个 batch、每个 head，需要计算：

Q[b,n,:,:] @ K[b,n,:,:].T  -> [S,S]

把 N 放在矩阵乘法的两个末尾维度 S、D 之前，PyTorch 就可以把 B、N 当作 batch 维，对所有 head 并行执行 batched matmul。

4. shape 相同，不代表内存顺序相同

transpose 通常不搬数据，只改变 stride，让新索引映射到原 storage。结果往往 non-contiguous。

操作承诺
view必须能用现有 shape/stride 解释同一 storage，否则失败
reshape返回目标 shape；能 view 就 view，否则可能复制
contiguous()按当前逻辑顺序生成连续布局
在 merge heads 时，常用 x.transpose(1,2).contiguous().view(B,S,N*D)。这里 contiguous 不是数学要求，而是 storage/stride 要求。
