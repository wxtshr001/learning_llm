从三维 Tensor 到 Attention Head

第 0001 课里，你处理的是一行一个 token 的二维矩阵。本课只增加两件事：一次同时处理多个序列，以及把每个 token 的长向量拆成多个较短的 head。所有字母先定义，再使用。

本课完成标准：看到 [B,S,H] 时能说出每个轴；能把它变成 [B,N,S,D]；能追踪一个具体元素在 reshape/transpose 前后的索引；能解释为什么 merge 前常用 contiguous()。

预计时间：讲解与探索 40～60 分钟，代码作业 30～60 分钟，闭卷测试 20 分钟。

1. 先把五个字母说清楚

这些字母只是为了少写长单词，不是新数学。每次使用时都应能换回中文含义。

B = Batch
一次同时处理多少条序列。
S = Sequence length
每条序列中有多少个 token。
H = Hidden size
每个 token 用多少个数表示。
N = Number of heads
Attention 被分成多少个 head。
D = Head dimension
每个 head 分到多少个特征。

它们满足：

H = N × D，所以 D = H ÷ N。

例如 hidden size 是 8，分成 2 个 head，那么每个 head 有 4 个特征：

H = 8
N = 2
D = H / N = 4
注意：head 不是新增 8 个数。原来的 8 个 hidden 特征被重新分组为 2 组，每组 4 个；元素总数不变。

2. shape、rank、axis/dim 分别是什么

假设一个 tensor 的 shape 为 [2,3,8]：

术语这里的含义
shape[2,3,8]，每个轴的长度。
rank / ndim3，因为有三个轴。这里不是矩阵秩。
axis / dim 0第一个轴，长度 2，本课表示 Batch。
axis / dim 1第二个轴，长度 3，本课表示 Sequence。
axis / dim 2第三个轴，长度 8，本课表示 Hidden。

所以：

x.shape = [B=2, S=3, H=8]

x[0, 1, 6]
│  │  └─ 第 6 个 hidden 特征
│  └──── 第 1 个 token
└─────── 第 0 条序列

Python 从 0 开始计数，因此“第 1 个 token”在自然语言里也可能被称为第二个 token。后续为了避免歧义，一律写“下标 1”。

3. 用具体数字看 reshape

先只看一条序列：B=1。序列有 3 个 token，每个 token 有 8 个 hidden 特征：

x.shape = [1, 3, 8]

token 下标 0: [ 0,  1,  2,  3,  4,  5,  6,  7]
token 下标 1: [ 8,  9, 10, 11, 12, 13, 14, 15]
token 下标 2: [16, 17, 18, 19, 20, 21, 22, 23]

现在令 N=2，因此 D=4。把最后一个长度 8 的轴拆成 2×4：

reshaped = x.reshape(B=1, S=3, N=2, D=4)
reshaped.shape = [1, 3, 2, 4]

token 0:
  head 0: [0, 1, 2, 3]
  head 1: [4, 5, 6, 7]

token 1:
  head 0: [8, 9, 10, 11]
  head 1: [12, 13, 14, 15]

reshape 没有改变数值顺序，只是把原来的 hidden 下标拆成：

hidden_index = head_index × head_dim + index_inside_head

例如 hidden_index 6:
6 = 1 × 4 + 2
所以它属于 head 下标 1，在这个 head 内的下标是 2。

因此：reshaped[0,0,1,2] == x[0,0,6] == 6。

4. transpose 只交换轴的位置

reshape 后的轴顺序是：

dim 0 = B = Batch
dim 1 = S = Sequence
dim 2 = N = Heads
dim 3 = D = Head dimension

shape = [B,S,N,D] = [1,3,2,4]

执行 transpose(1,2)，意思是交换 dim 1 与 dim 2：

heads = reshaped.transpose(1, 2)

交换前: [B, S, N, D] = [1, 3, 2, 4]
交换后: [B, N, S, D] = [1, 2, 3, 4]

任何轴的长度都没有“计算出新值”；只是长度 3 的 Sequence 轴和长度 2 的 Head 轴互换位置。

元素映射也只是换索引顺序：

heads[b,n,s,d] = reshaped[b,s,n,d] = x[b,s,n×D+d]

例如：

heads[0,1,0,2]
= reshaped[0,0,1,2]
= x[0,0,6]
= 6

5. 为什么 Attention 喜欢 [B,N,S,D]

现在先不学习 Attention 公式，只看组织方式。对某一个 batch、某一个 head，我们希望拿到“所有 token 在这个 head 中的向量”：

heads[b, n, :, :]

shape = [S, D]
含义 = 这一条序列的所有 token，每个 token 只保留当前 head 的 D 个特征

以后单个 head 的 Q 和 K 会进行：

Q_head: [S,D]
K_head: [S,D]
Q_head @ K_head.transpose(-2,-1): [S,S]

把 B、N 放在前面，就能把它们当成两层“批次”，让 PyTorch 同时计算所有 batch 的所有 head。你现在只需掌握 layout，不需要提前理解完整 Attention。

6. stride 与 contiguous：先用 C++ 内存理解

你有 C++/系统经验，可以把 tensor 想成：

  • 一块线性 storage；
  • 一个 shape，说明每个轴有多长；
  • 一个 stride，说明某个轴的下标增加 1 时，在线性 storage 中跳过多少个元素。

连续的 [2,3,4] tensor 通常有 stride：

shape  = [2, 3, 4]
stride = [12, 4, 1]

offset(i,j,k) = i×12 + j×4 + k×1

执行 transpose(1,2) 后，storage 通常没有搬动，只交换 shape 与 stride 的解释：

shape  = [2, 4, 3]
stride = [12, 1, 4]

这时逻辑索引仍正确，但数据不再按最后一维连续排列，所以 tensor 通常是 non-contiguous。

API本课需要记住的行为
view(new_shape)只改解释，不复制；因此要求当前 stride 能支持新 shape，否则报错。
reshape(new_shape)保证给出目标 shape；能共享 storage 就共享，不能时可能复制。不要依赖它一定复制或一定不复制。
contiguous()按当前逻辑顺序整理出连续 storage，然后可安全使用常规 view。
当前门槛：你不需要手算复杂 stride；只需能解释为什么 transpose 后直接 view 可能失败，以及为什么 contiguous().view(...) 能工作。
