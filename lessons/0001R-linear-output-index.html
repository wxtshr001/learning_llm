为什么 Linear 的 bias 是 b[j]

你的程序已经正确使用 b[j]，但闭卷公式和 Debug 题都写成了 b[i]。这说明问题不在 Python，而在“输出行”和“输出特征”尚未稳定绑定。

只记一个对象：Y[i,j]

i 选择输出的哪一行：在 LLM 里通常是哪个 token。

j 选择输出的哪一列：也就是哪个输出特征。

bias 每个输出特征一个，因此使用 b[j]。

Y[i,j] = X[i,0]×W[0,j]
       + X[i,1]×W[1,j]
       + ...
       + X[i,K-1]×W[K-1,j]
       + b[j]

改变 i：换一个 token，但仍计算同一个输出特征 j。改变 j：换一个输出特征，因此 bias 也必须跟着 j 改变。

逐元素手算，而不是整块猜答案

X = [[1, 2],       W = [[1, 0],       b = [10, 20]
     [3, 4]]            [0, 2]]
元素dot productbias结果
Y[0,0]1×1 + 2×0+ b[0] = 1011
Y[0,1]1×0 + 2×2+ b[1] = 2024
Y[1,0]3×1 + 4×0+ b[0] = 1013
Y[1,1]3×0 + 4×2+ b[1] = 2028
自检：同一列的所有输出都加同一个 bias；同一行的不同列通常加不同 bias。

为什么代码对、闭卷却错

你的代码通过 j 取 W 的第 j 列，随后正确写了 + b[j]。但旁边注释和闭卷答案写成 b[i]。这类“代码流畅、索引心智模型不稳定”的问题在 Q/K/V reshape、KV Cache update 中会放大，所以现在修正很划算。

回到练习代码，把错误注释也改成：

# x[i,:] · w[:,j] + b[j]
