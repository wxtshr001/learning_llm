0008：RoPE——让 Q/K 的匹配感知 token 位置

RoPE 是 Rotary Position Embedding，中文常译“旋转位置编码”。第 0007 课已经证明 GQA 如何生成、映射和合并多个 heads；本课第一次完整讲授 RoPE，而不是把它作为一句式预告。

1. 进入条件、本节成果与系统坐标

可以直接使用：你已经能解释 Q/K/V 分工、score 点积、[B,N,S,D] 的所有 axis、GQA 的 Nq/Nkv 差异，以及 merge/o_proj。

必须从零解释：位置为什么需要进入 attention、二维旋转、Qwen 风格的 half-split 配对、position_ids、inv_freq、cos/sin 广播，以及 RoPE 在 full-sequence/prefill/decode 中的位置。

hidden_states [B,S,H]
→ RMSNorm → q/k/v projections → split heads
→ Q [B,Nq,S,D] ─┐
                  ├→ RoPE 只旋转 Q/K → GQA causal attention
→ K [B,Nkv,S,D] ─┘
→ V [B,Nkv,S,D] ────────────────────→ value aggregation
→ head outputs → merge → o_proj → residual add

B 是 batch size；S 是 token 数；H 是 hidden size；Nq 是 Q head 数；Nkv 是 K/V head 数；D 是每个 head 的特征数。

本节成果：实现 Qwen 风格 RoPE，使 Q/K shape 和向量长度保持不变，并用具体点积说明相同相对距离产生相同位置效应。

2. 为什么 attention 需要位置信息

第 0006 课的 score 是 Q[q]·K[k]。如果两个 token 的内容向量完全相同，而计算里没有任何位置输入，那么“第 1 个 token”和“第 10 个 token”对点积来说没有区别。

RoPE 不把一个 position vector 直接加到 hidden state；它根据 token 的 position，把 Q 和 K 的二维特征对旋转不同角度。于是 score 同时取决于内容方向和两个 token 的相对位置。

RoPE 不是 causal mask。RoPE 让 score 感知距离；causal mask 仍负责禁止看未来。两者职责不同，不能互相替代。

3. 先只看二维：旋转到底做了什么

一个二维向量 x=[a,b] 逆时针旋转角度 θ 后：

x_rot[0] = a*cos(θ) - b*sin(θ)
x_rot[1] = a*sin(θ) + b*cos(θ)

例如 x=[3,4]，旋转 90° 时 cos=0、sin=1：

x_rot = [3*0 - 4*1, 3*1 + 4*0] = [-4,3]

旋转前长度 = sqrt(3²+4²) = 5
旋转后长度 = sqrt((-4)²+3²) = 5

旋转改变方向，不改变长度。这是后面检查实现正确性的一个不变量。

4. Qwen 的 D=4 配对不是相邻元素

原始论文常用相邻配对 (x0,x1)、(x2,x3) 展示旋转。当前 Hugging Face Qwen 风格实现采用 half-split layout：先把最后一维分成前后两半，所以 D=4 时配对是 (x0,x2)、(x1,x3)。

x = [x0,x1,x2,x3]
first_half  = [x0,x1]
second_half = [x2,x3]

rotate_half(x) = [-x2,-x3,x0,x1]

取 x=[1,2,3,4]：

rotate_half(x) = [-3,-4,1,2]

假设第一对 (x0,x2) 旋转 90°，第二对 (x1,x3) 旋转 0°，则：

cos = [0,1,0,1]
sin = [1,0,1,0]

x_rope = x*cos + rotate_half(x)*sin
       = [1,2,3,4]*[0,1,0,1] + [-3,-4,1,2]*[1,0,1,0]
       = [-3,2,1,4]

第一对从 [1,3] 变成 [-3,1]；第二对 [2,4] 不变。不要把 half-split 的 rotate_half 错写成相邻元素交换。

5. position_ids 怎样变成 cos/sin

position_ids 是每个 token 的整数位置，shape 为 [B,S]。例如一条长度 3 的序列是 [[0,1,2]]。

RoPE 给每个二维特征对一个不同的旋转频率。设 pair index 为 i，范围是 0..D/2-1：

inv_freq[i] = 1 / base^(2*i/D)
angle[b,s,i] = position_ids[b,s] * inv_freq[i]

base 是频率基数，标准示例常取 10000。inv_freq shape 是 [D/2]；angle shape 是 [B,S,D/2]。Qwen half-split 需要把 angles 复制一次：

angles [B,S,D/2]
→ concat(angles, angles) = embedding [B,S,D]
→ cos = cos(embedding), sin = sin(embedding)

position 0 的 angle 全为 0，所以 cos=1、sin=0，RoPE 是恒等变换。position 越大，同一频率对应的旋转角越大。

本课只学习默认 RoPE。linear、dynamic、YaRN、LongRoPE 等长上下文缩放变体暂不进入门禁。

6. GQA 中 cos/sin 怎样广播

取 B=2、S=5、Nq=6、Nkv=2、D=4：

tensorrank/shapeaxis 含义
position_idsrank 2，[2,5]batch、token position
cos/sinrank 3，[2,5,4]batch、token position、head feature
unsqueeze 后 cos/sinrank 4，[2,1,5,4]head axis 长度 1，可广播
Qrank 4，[2,6,5,4][B,Nq,S,D]
Krank 4，[2,2,5,4][B,Nkv,S,D]
Q_rope[2,6,5,4]shape 与 Q 相同
K_rope[2,2,5,4]shape 与 K 相同
V[2,2,5,4]不经过 RoPE

[B,1,S,D] 的 head axis 会分别广播到 6 个 Q heads 和 2 个 K heads，所以 Q/K head 数不同不妨碍使用同一组 position cos/sin。K 在仍为 Nkv 时旋转，不需要先 repeat 到 Nq。

7. 为什么它表达相对位置

设二维旋转矩阵为 R(position*θ)。Q 在位置 m，K 在位置 n：

score_position_part
= (R(mθ) q) · (R(nθ) k)
= q · R((n-m)θ) k

最终只留下相对位置 n-m。用每步旋转 90° 的最小例子：

原始 q=k=[1,0]
position 0 → [ 1,0]
position 1 → [ 0,1]
position 2 → [-1,0]

score(0,1) = [1,0]·[0,1]  = 0
score(1,2) = [0,1]·[-1,0] = 0   # 相对距离同为 1
score(0,2) = [1,0]·[-1,0] = -1  # 相对距离为 2

这不是说真实模型的所有 score 只由距离决定；Q/K 的内容也参与。这里证明的是 position 的影响以相对差进入点积。

8. 为什么旋转 Q/K，不旋转 V

Q/K 决定“当前 query 应该从哪些 key positions 取信息”，因此位置要进入它们的匹配 score。V 是被权重汇集的内容载体：

Q_rope @ K_ropeᵀ → scores → mask → softmax → weights
weights @ V → head_output

如果把 V 也旋转，就会直接改变被汇集的内容表示；这不是本课和 Qwen 实现采用的 RoPE 语义。代码接口因此返回旋转后的 Q/K，V 原样沿后续路径使用。

9. full-sequence、prefill、decode 与 Cache 的边界

阶段position_idsRoPE 行为
full-sequence/prefill通常为 0..S-1一次为全部 Q/K positions 构造 cos/sin 并旋转
单步 decode新 token 使用其绝对位置，如已有 5 个 token 时新位置为 5只旋转新 Q/K；不能每步都把位置重置为 0

当前 Qwen 风格顺序是：split 后得到 Q/K/V → 对 Q/K 应用 RoPE → 若启用 Cache，追加旋转后的 K 和未旋转的 V → attention。0010 才会实现 Cache 的增量更新与 full-vs-decode parity；0008 只验收 RoPE 本身和这个明确位置。

10. PyTorch 实现逐行对应

def rotate_half(x):
    half = x.shape[-1] // 2
    x1 = x[..., :half]
    x2 = x[..., half:]
    return torch.cat((-x2, x1), dim=-1)

cos = cos.unsqueeze(1)  # [B,S,D] → [B,1,S,D]
sin = sin.unsqueeze(1)
q_rope = q * cos + rotate_half(q) * sin
k_rope = k * cos + rotate_half(k) * sin

... 表示保留前面所有 axis，只切最后一个 axis。unsqueeze(1) 在 axis 1 插入长度 1 的 head 维。逐元素写法是：

q_rope[b,n,s,d]
= q[b,n,s,d] * cos[b,s,d]
  + rotate_half(q)[b,n,s,d] * sin[b,s,d]

必须检查：D 为正偶数；Q/K 的 B、S、D 相同；cos/sin 是 [B,S,D]；device/dtype 相容。RoPE 不改变任何 tensor 的元素总数或 shape。

11. Parameter、Activation 与 State

对象类别说明
q/k projection weightsParameter训练学习并保存在 checkpoint
position_ids、cos、sin、Q_rope、K_ropeActivation/运行输入本次请求根据位置计算；默认 RoPE 没有为每个位置学习一张 Parameter 表
inv_freq确定性配置/常见 buffer由 base 与 D 计算；实现中可缓存，但不是普通可训练 Parameter
旋转后的历史 K 与 V请求 Statedecode Cache，0010 实现生命周期

对 export/runtime，RoPE 可能表现为 arange、乘法、cos、sin、slice、neg、cat 和逐元素运算，也可能被后端融合。无论图如何变化，Q/K shape、不旋转 V、position 0 恒等和长度保持是可用于对齐的不变量。
