0008：RoPE 通俗详解——把 token 位置变成 Q/K 的旋转角

先不要管论文公式。RoPE 做的事情可以先压缩成一句人话：

同一个 Q 或 K 向量，token 所在位置不同，就把它朝不同方向旋转；Attention 比较 Q 和 K 时，既比较内容，也感受到两个 token 相隔多远。

RoPE 全称 Rotary Position Embedding，中文常译“旋转位置编码”。本课会从钟表指针和二维坐标开始，把每一个数字算清楚，再接到 Qwen 的 GQA 和 PyTorch。

0. 这次可以依赖什么，不能假设什么

已经掌握，可以直接使用：

  • Q 用来发起查询，K 用来匹配，V 是最终被取回的内容。
  • GQA 中 Q 是 [B,Nq,S,D]，K/V 是 [B,Nkv,S,D]。
  • score 来自 Q 与 K 的点积；V 不参与 score。
  • 会追踪 reshape、transpose、broadcast 和每个 axis。

本课从零讲，不假设你会：

  • 角度、弧度、cos、sin 在旋转中分别做什么。
  • 为什么 D 个特征要两两配对。
  • Qwen 的 rotate_half 为什么得到 [-x2,-x3,x0,x1]。
  • position_ids 怎样一步步变成 cos/sin。
  • 为什么最终的 Q·K 点积能感受到相对位置。

完成本课后：你能手算一个 D=4 向量的 Qwen-style RoPE，能实现代码，并能指出它在 GQA/Cache 路径中的准确位置。

1. 先建立最小直觉：钟表指针就是二维向量

把二维向量 [x,y] 想成一根从原点出发的箭头。为了手算方便，本课采用数学坐标：x 轴向右，y 轴向上，正角度表示逆时针旋转。

0°
向右
[1,0]
90°
向上
[0,1]
180°
向左
[-1,0]
270°
向下
[0,-1]

所以 [1,0] 旋转 90° 变成 [0,1]；再旋转 90° 变成 [-1,0]。这就是本课所有高维公式的最小核心。

角度和弧度

手算时我们说 90°，代码中的 torch.sin()/torch.cos() 使用弧度：

角度弧度cossin
0°010
90°π/201
180°π-10
270°3π/20-1

π（读作 pi）约等于 3.14159。你不需要在闭卷题里计算任意角度的三角函数；题目会给出可手算的 cos/sin。

2. cos 和 sin 为什么能完成旋转

一个二维向量 [a,b] 旋转角度 θ 后：

新 x = a*cos(θ) - b*sin(θ)
新 y = a*sin(θ) + b*cos(θ)

先不要背。代入 90° 的 cos=0、sin=1：

新 x = a*0 - b*1 = -b
新 y = a*1 + b*0 =  a

所以 [a,b] 旋转 90° → [-b,a]

拿具体数字 [3,4]：

[3,4] 旋转 90° → [-4,3]

用坐标画面理解：原来向右 3、向上 4；旋转后向左 4、向上 3。

旋转不会改变箭头长度

旋转前长度 = sqrt(3² + 4²) = 5
旋转后长度 = sqrt((-4)² + 3²) = 5

因此“每个 head vector 的长度保持不变”可以成为代码测试。若旋转后长度明显变化，通常是配对、cos/sin 排列或符号写错。

3. 从 D=2 走到 D=4：不是四维一起转，而是两个二维平面

D 是 head dimension，即每个 Attention head 拥有的特征数。若 D=4，RoPE 会把 4 个数分成两个二维向量，分别旋转。

关键问题变成：哪两个 axis 配成一对？

布局D=4 的两对 axis常见展示位置
相邻配对(0,1)、(2,3)RoFormer 论文公式常这样展示
Qwen/Hugging Face half-split(0,2)、(1,3)本课代码和 Qwen reference
本课统一使用 Qwen half-split。不要把论文的相邻配对索引直接抄进 Qwen-style 代码。两种方式都表达二维旋转，但内存排列不同。

对 x=[x0,x1,x2,x3]：

前半段 first_half  = [x0,x1]
后半段 second_half = [x2,x3]

配对：x0 ↔ x2
      x1 ↔ x3

为什么 D 必须是偶数？因为每个二维平面必须正好拿两个特征。D=5 会剩下一个无法配对的特征。

4. 把 rotate_half 拆成一张逐元素表

Qwen-style 代码：

first  = x[..., :D/2]
second = x[..., D/2:]
rotate_half(x) = concat(-second, first)

取 x=[1,2,3,4]，D=4，D/2=2：

输出 axis d取哪个输入是否变号输出值它服务哪一对
0x[2]=3是-3(x0,x2) 的新 x 交叉项
1x[3]=4是-4(x1,x3) 的新 x 交叉项
2x[0]=1否1(x0,x2) 的新 y 交叉项
3x[1]=2否2(x1,x3) 的新 y 交叉项
rotate_half([1,2,3,4]) = [-3,-4,1,2]

这恰好把二维公式中的 [-b,a] 同时应用到两对轴上：

pair 0: [x0,x2]=[1,3] → rotate helper [-3,1]
pair 1: [x1,x3]=[2,4] → rotate helper [-4,2]

5. 完整手算一次 x*cos + rotate_half(x)*sin

仍用 x=[1,2,3,4]。假设：

  • pair 0，也就是 axis (0,2)，旋转 90°：cos=0、sin=1。
  • pair 1，也就是 axis (1,3)，旋转 0°：cos=1、sin=0。

为了让同一对 axis 使用同一个角度，Qwen 排列为：

cos = [pair0_cos, pair1_cos, pair0_cos, pair1_cos]
    = [0,         1,         0,         1]

sin = [pair0_sin, pair1_sin, pair0_sin, pair1_sin]
    = [1,         0,         1,         0]

逐 axis 计算：

dx[d]*cos[d]rotate_half[d]*sin[d]相加
01*0=0-3*1=-3-3
12*1=2-4*0=02
23*0=01*1=11
34*1=42*0=04
x_rope = [-3,2,1,4]

重新按二维 pair 查看：

pair 0: [axis0,axis2] = [1,3] → [-3,1]  # 旋转 90°
pair 1: [axis1,axis3] = [2,4] → [ 2,4]  # 旋转 0°

到这里，RoPE 的核心逐元素计算已经完成。后面的 position_ids、inv_freq 只负责回答“每个 pair 到底应该旋转多少度”。

6. position_ids 是什么：先别想频率，只想 token 编号

position_ids 就是 token 在当前生成序列中的位置编号。

token:        我    喜    欢
position:    0     1     2
position_ids = [[0,1,2]]

shape 是 [B,S]：

  • B（batch size）= 同时处理几条序列。
  • S（sequence length）= 每条序列有几个 token。

若 B=1,S=3，shape 是 [1,3]。这不是 embedding，也没有 D axis；它只是整数位置表。

先使用一个人为简化的旋转速度

为了理解，假设 pair 0 每走一个 position 转 90°，pair 1 每走一个 position 转 0°：

positionpair 0 角度pair 1 角度
00°0°
190°0°
2180°0°

position 0 没旋转；position 1 的第一对转 90°；position 2 的第一对转 180°。这就是“位置乘以旋转速度”。

7. inv_freq 只是“每前进一个 token，要转多快”

inv_freq 是 inverse frequency（逆频率）。名字容易吓人，本课把它直接理解为：每个二维 pair 的基础旋转速度。

angle = position * inv_freq

上面的简化例子用弧度写：

inv_freq = [π/2, 0]  # pair0 每步 90°，pair1 每步 0°
position_ids = [[0,1,2]]

angles =
position 0: [0*(π/2), 0*0] = [0,   0]
position 1: [1*(π/2), 1*0] = [π/2, 0]
position 2: [2*(π/2), 2*0] = [π,   0]

shape 变化：

position_ids [B,S]     = [1,3]
inv_freq    [D/2]     = [2]
angles      [B,S,D/2] = [1,3,2]

真实默认 RoPE 不会用 `[π/2,0]`，而是让不同 pair 有不同速度：

inv_freq[i] = 1 / base^(2*i/D)

这里：

  • i 是 pair index，从 0 到 D/2-1。
  • base 是配置中的频率基数，常见值为 10000。
  • 前面的 pair 旋转较快，后面的 pair 旋转较慢，从而同时表示短距离与长距离变化。

用 D=4、base=10000 把真实公式算一遍。此时有两个 pair，所以 i=[0,1]：

pair 0: i=0
inv_freq[0] = 1 / 10000^(2*0/4)
            = 1 / 10000^0
            = 1

pair 1: i=1
inv_freq[1] = 1 / 10000^(2*1/4)
            = 1 / 10000^0.5
            = 1 / 100
            = 0.01

所以 inv_freq = [1, 0.01]

若 token 的 position 是 2，两个 pair 的角度就是 [2*1, 2*0.01]=[2,0.02] 弧度。代码再对它们取 cos/sin。这里不要求手算 cos(2)；重点是看懂 position 与每个 pair 的旋转速度怎样相乘。

两套数字不要混淆：引导脚本使用 [π/2,0]，目的是让 90° 可以手算；独立作业的 build_rope_cos_sin() 使用上面的真实默认公式。

现阶段要会实现这个公式，但不要求推导它为什么选 10000，也不学习 YaRN、dynamic、LongRoPE 等缩放变体。

8. 为什么 angles 要复制：从 D/2 回到 D

每个 pair 只有一个角度，但一个 pair 占两个 axis。Qwen half-split 要让 axis 0 和 axis 2 使用同一个角度，让 axis 1 和 axis 3 使用同一个角度。

angles = [angle_pair0, angle_pair1]  # [D/2]

复制后 embedding = [angle_pair0, angle_pair1,
                    angle_pair0, angle_pair1]  # [D]

再分别取 cos 和 sin：

cos = embedding.cos()
sin = embedding.sin()

完整 shape 链：

阶段具体 shape（B=1,S=3,D=4）每个 axis
position_ids[1,3]batch、token
inv_freq[2]pair
angles[1,3,2]batch、token、pair
embedding/cos/sin[1,3,4]batch、token、head feature

position 0 的 angle 都是 0，所以 cos 都是 1、sin 都是 0：

x_rope = x*1 + rotate_half(x)*0 = x

因此 position 0 必须保持原向量不变，这是非常好用的单元测试。

9. 现在把一个 token 的 Q 和 K 放进来

假设某个 token 在 position 1，它的一个 Q head 是：

Q = [1,2,3,4]

仍使用 pair 0 转 90°、pair 1 转 0° 的简化 cos/sin：

Q_rope = [-3,2,1,4]

同位置的某个 K head 假设为：

K = [10,20,30,40]
rotate_half(K) = [-30,-40,10,20]
K_rope = [-30,20,10,40]

注意两件事：

  1. Q 和 K 使用相同 position 对应的 cos/sin，但原始内容不同，所以旋转后数值也不同。
  2. RoPE 没有把 Q/K 变成“位置向量”；它保留原内容，只改变二维特征对的方向。

10. 为什么同时旋转 Q 和 K：点积看到的是角度差

Q/K 点积可以把箭头方向相似程度变成 score。用最小二维例子，原始 Q=K=[1,0]，每前进一个 position 旋转 90°：

position旋转后向量
0[1,0]
1[0,1]
2[-1,0]

计算三次点积：

score(0,1) = [1,0] · [ 0,1] = 0
score(1,2) = [0,1] · [-1,0] = 0
score(0,2) = [1,0] · [-1,0] = -1

(0,1) 和 (1,2) 的相对距离都为 1，所以位置带来的 score 效应相同。(0,2) 相距 2，效果不同。

现在才引入压缩公式：

(R(mθ)q) · (R(nθ)k) = q · R((n-m)θ)k

读法：

  • R(mθ)：把 Q 按位置 m 旋转。
  • R(nθ)：把 K 按位置 n 旋转。
  • 两者点积后，位置影响只剩角度差 (n-m)θ。

你不需要证明矩阵等式；只需要能用上面的具体向量解释“相同相对距离 → 相同的位置旋转差”。

11. RoPE 和 causal mask 完全不是一件事

组件回答的问题做法
RoPE两个 token 相隔多远、方向关系如何影响匹配？旋转 Q/K，改变 score
causal mask当前 token 是否允许看到某个未来 token？把未来位置 score 设为负无穷

即使有 RoPE，position 0 仍可能对 position 10 算出一个有限 score；必须再用 causal mask 才能禁止看未来。因此 RoPE 不能替代 causal mask。

12. 为什么只旋转 Q/K，不旋转 V

把 Attention 分成两步：

第一步：Q_rope @ K_ropeᵀ → scores → weights
        决定“去哪些位置取信息”

第二步：weights @ V → head_output
        按权重取回内容

位置应该影响“匹配谁”，所以进入 Q/K。V 是被取回的内容，不参与 Q·K score；Qwen 的 RoPE 不旋转 V。

类比 C++ 数据处理：

  • Q/K 像查找键和索引比较规则。
  • V 像命中索引后取回的 payload。
  • RoPE 修改比较规则中的位置方向，不直接改 payload。

13. 接回 GQA：Nq 和 Nkv 不同也能直接旋转

取一个具体配置：

B=2：两条序列
S=5：每条 5 个 token
Nq=6：6 个 Q heads
Nkv=2：2 个 K/V heads
D=4：每个 head 4 个特征

RoPE 前：

Q [B,Nq,S,D]  = [2,6,5,4]
K [B,Nkv,S,D] = [2,2,5,4]
V [B,Nkv,S,D] = [2,2,5,4]
cos/sin        = [2,5,4]

cos/sin 没有 head axis。为了和 rank-4 的 Q/K 对齐，在 axis 1 插入长度 1：

cos.unsqueeze(1): [2,5,4] → [2,1,5,4]
sin.unsqueeze(1): [2,5,4] → [2,1,5,4]

广播过程：

计算head axis结果
Q × cos6 × 1，把同一 position 角度广播给 6 个 Q heads[2,6,5,4]
K × cos2 × 1，把同一 position 角度广播给 2 个 K heads[2,2,5,4]

所以不需要先 repeat K。RoPE 只依赖 position 和 D，不依赖 head 数。旋转后：

Q_rope [2,6,5,4]  # shape 不变
K_rope [2,2,5,4]  # shape 不变
V      [2,2,5,4]  # 数值和 shape 都不变

14. 完整执行顺序：这次每一步都说明职责

hidden_states [B,S,H]
  → RMSNorm
  → q_proj / k_proj / v_proj
  → split + transpose
       Q [B,Nq,S,D]
       K [B,Nkv,S,D]
       V [B,Nkv,S,D]
  → 根据 position_ids 生成 cos/sin [B,S,D]
  → RoPE(Q,K)
       Q_rope [B,Nq,S,D]
       K_rope [B,Nkv,S,D]
       V 不变
  → 若使用 Cache：保存/追加 K_rope 与 V
  → GQA：K/V 按组供 Nq 个 Q heads 使用
  → causal attention
  → head outputs → merge → o_proj
  → residual add
步骤做了什么是否混合 token
projection从 hidden 生成 Q/K/V 内容否，每个 token 独立
RoPE按各 token 的 position 旋转自己的 Q/K否，每个 token 独立
Q·K 与 softmax比较 query position 与多个 key positions是，Attention 在这里跨 token
weights·V从多个位置汇集内容是

RoPE 本身不会把 token 0 的数据读进 token 1；它只是让两个 token 后续比较时带有位置差。

15. Prefill 和 decode：position_id 不能每次从 0 开始

Prefill

一次输入 5 个 prompt tokens：

position_ids = [[0,1,2,3,4]]

一次生成所有位置的 cos/sin，旋转全部 Q/K。

单步 decode

Cache 已有 5 个 tokens，新 token 是全局 position 5：

新 token position_id = [[5]]

若错误地重置成 0，新 Q/K 会使用 position 0 的恒等旋转，模型会把新 token 当成序列开头，和历史 K 的相对位置关系全部错位。

Qwen 风格顺序是：

新 Q/K → 使用全局 position 做 RoPE
→ 把旋转后的新 K 与未旋转的 V 追加到 Cache
→ 当前 Q 与历史 Cache 做 Attention

0010 才实现 Cache 的完整增量更新；0008 只要求理解和验证这个位置关系。

16. PyTorch 代码逐行翻译成人话

def rotate_half(x):
    half = x.shape[-1] // 2       # D/2
    first = x[..., :half]         # 前半段
    second = x[..., half:]        # 后半段
    return torch.cat((-second, first), dim=-1)

... 表示前面的 B、N、S axis 全部原样保留，只切最后的 D axis。

cos = cos.unsqueeze(1)  # [B,S,D] → [B,1,S,D]
sin = sin.unsqueeze(1)

q_rope = q * cos + rotate_half(q) * sin
k_rope = k * cos + rotate_half(k) * sin

对 Q 的某一个元素：

q_rope[b,n,s,d]
= q[b,n,s,d] * cos[b,s,d]
  + rotate_half(q)[b,n,s,d] * sin[b,s,d]

cos/sin 没有 n 索引，因为同一 batch、同一 token position、同一 feature pair 对所有 heads 使用相同角度；PyTorch 通过长度 1 的 head axis 自动广播。

16.1 独立作业的输入契约：哪些不满足时必须报错

“输入契约”就是函数接受什么 shape、数据类型和设备。作业不是要求你猜这些条件；下面逐项列全。

函数必须满足为什么
rotate_half(x)最后一维 D>0 且为偶数每两个特征组成一个二维 pair，奇数 D 会剩一个
build_rope_cos_sin(position_ids,D,base)position_ids 是 rank-2 的整数 tensor [B,S]它保存离散 token 编号，不是浮点特征
同上D>0 且为偶数；base>0D 要配对；非正 base 无法按默认公式生成有效频率
apply_rope(Q,K,cos,sin)Q/K 都是 rank-4 [B,N,S,D]，并拥有相同 B、S、Dhead 数 N 可以不同，其余三个 axis 必须对应同一批 token 和同一特征布局
同上Q、K、cos、sin 在同一个 deviceCPU tensor 与 CUDA tensor 不能直接逐元素相乘
同上Q、K、cos、sin 使用相同 dtype本作业要求输出精度与输入明确一致，禁止依赖隐式类型提升
同上cos/sin 都是 [B,S,D]插入 head axis 后才能广播为 [B,1,S,D]

例如 Q 是 float32，cos 却是 float64，即使某些 PyTorch 运算可能自动提升类型，本作业也要求主动抛出 ValueError。这是明确的作业接口要求，不是 RoPE 数学定理。

推荐检查顺序：先 rank → 再 B/S/D → 再 D 是否正偶数 → 再 device → 再 dtype → 最后做旋转。这样报错更接近真正原因。

19. 四个必须保持的不变量

  1. shape 不变：Q_rope 与 Q 相同，K_rope 与 K 相同。
  2. position 0 恒等：cos=1、sin=0，输出等于输入。
  3. 长度保持：每个二维 pair 以及整个 head vector 的 L2 长度（即 sqrt(sum(x²))）不变。
  4. V 不变：RoPE 只旋转 Q/K。

这些不变量以后会用于 eager、export、converter、backend 和 runtime 分层对齐。即使设备 kernel 把 RoPE 融合了，语义仍必须满足它们。
