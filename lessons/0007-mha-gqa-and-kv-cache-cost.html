0007：从 MHA 到 GQA——Head 映射与 KV Cache 成本

第 0006 课已经证明一个 attention head 怎样计算 score、mask、softmax 和 value 加权。本课不重复这条公式，而是回答三个系统问题：为什么并行多个 head？为什么现代 decoder 常让多个 Q head 共享较少的 K/V head？这怎样减少参数、KV Cache 容量和 decode 时的内存流量？

1. 本课在 Transformer 数据流中的位置

hidden_states [B,S,H]
  → RMSNorm
  → q_proj / k_proj / v_proj
  → split heads
       Q [B,Nq,S,D]
       K [B,Nkv,S,D] ─┐
       V [B,Nkv,S,D] ─┴→ 按组供 Nq 个 Q head 使用
  → 每个 Q head 独立执行第 0006 课的 causal attention
  → head outputs [B,Nq,S,D]
  → transpose + merge → [B,S,Nq*D]
  → o_proj → [B,S,H]
  → residual add

B 是 batch size；S 是 sequence length；H 是 residual stream 的 hidden size；D 是每个 head 的特征数；Nq 是 query head 数；Nkv 是 key/value head 数。这里 Q、K、V 都是 rank 4 tensor：axis 0=batch，axis 1=head，axis 2=token position，axis 3=head feature。

本课可依赖：单头 causal attention、两个求和轴、[B,S,H] ↔ [B,N,S,D] split/merge、Linear 与 decoder residual 路径已经通过。
必须从零解释：MHA/MQA/GQA 区别、Q→KV head 映射、projection width、Cache 字节公式，以及 prefill/decode 中真正节省了什么。

2. 为什么不只用一个 head

MHA 是 Multi-Head Attention（多头注意力）。它把一次宽向量匹配拆成多个并行的 attention 子空间。每个 head 有自己对应的 projection 参数，因此可学到不同的 Q/K 匹配方式和 V 内容变换。

先取最小的 H=4、Nq=2、D=2。一个 token 的 normed hidden vector 是 x=[x0,x1,x2,x3]。q_proj 不是简单把 x 原样切两半，而是先用训练参数产生 4 个新数，再 reshape：

q_proj(x) = [q00,q01,q10,q11]       # width Nq*D = 2*2 = 4
reshape → Q head 0 = [q00,q01]
          Q head 1 = [q10,q11]

两个 head 分别执行第 0006 课的 attention，得到两个长度 D 的 context。它们不是平均，而是按 head 顺序拼接，再由 output projection 混合回 H：

head_contexts = [[c00,c01], [c10,c11]]
merge          = [c00,c01,c10,c11]   # width Nq*D
attention_delta = o_proj(merge)       # width H

可以类比为多个并行的“匹配与读取通道”，最后由 o_proj 汇总。类比边界是：不能预先规定某个 head 必然负责语法或指代；head 的功能由训练结果决定。

3. MHA、MQA、GQA 是同一条轴上的三个点

结构Q head 数K/V head 数共享关系
MHANqNkv=Nq每个 Q head 有自己的一对 K/V head
GQANq1<Nkv<Nq每组多个 Q head 共享一对 K/V head
MQANqNkv=1所有 Q head 共享唯一一对 K/V head

GQA 是 Grouped-Query Attention（分组查询注意力）；MQA 是 Multi-Query Attention（多查询注意力）。GQA 的合法条件：

Nq % Nkv == 0
group_size = Nq // Nkv

若 Nq=4、Nkv=2，每个 KV head 服务 2 个相邻 Q head：

Q head:       0   1   2   3
KV head:     0   0   1   1
公式: kv_head = q_head // group_size

若 Nkv=Nq=4，group_size=1，退化为 MHA。若 Nkv=1，group_size=4，退化为 MQA。

不要把“共享 K/V”理解为合并或平均 Q：Q head 仍有 4 个，每个 Q head 都单独产生自己的 scores、weights 和 output；只是 head 0/1 在计算时读取同一份 K0/V0，head 2/3 读取同一份 K1/V1。

4. 用 Nq=4、Nkv=2 的数字完整追踪映射

令 B=1、S=2、D=1。为了把注意力权重简化成均匀值，所有 Q/K 都设为 0；因此每个 head 的 q0 权重是 [1,0]，q1 权重是 [1/2,1/2]。两组 V 内容不同：

KV head 0 的 V: position 0=1,  position 1=3
KV head 1 的 V: position 0=10, position 1=30

Q head 0 → KV head 0
Q head 1 → KV head 0
Q head 2 → KV head 1
Q head 3 → KV head 1

于是每个 Q head 的输出为：

position q0: [head0=1, head1=1, head2=10, head3=10]
position q1: [head0=2, head1=2, head2=20, head3=20]

merge 后按 token 排列：

merged [B,S,Nq*D] = [[[1,1,10,10],
                      [2,2,20,20]]]

这个例子里，同组 Q head 输出相同是因为我们故意让所有 Q/K 相同。真实模型中，同组 Q head 的 Q projection 不同，所以即使共享 K/V，它们的 scores 和 weights 仍可不同。

5. Tensor shape：哪些 head 轴相同，哪些不同

取 B=2、S=5、H=16、Nq=4、Nkv=2、D=4：

阶段shape来源
hidden_states[2,5,16]residual stream
q_proj raw[2,5,16]Nq*D=4*4=16
k_proj/v_proj raw[2,5,8]Nkv*D=2*4=8
Q split[2,4,5,4][B,Nq,S,D]
K/V split，Cache 保存形态[2,2,5,4][B,Nkv,S,D]
K/V 计算映射后的逻辑形态[2,4,5,4]每个 KV head 映射给 group_size=2 个 Q head
scores/weights[2,4,5,5]每个 Q head 都有自己的 q×k 表
head output[2,4,5,4]仍保留 Nq 个输出 head
merge[2,5,16]Nq*D=16
o_proj output[2,5,16]回到 residual stream 的 H

关键不变量：GQA 只减少 K/V head 轴；Q head 数、attention output head 数和 merge width 仍由 Nq 决定。

6. Projection 参数：具体省在哪里

沿用 H=16、Nq=4、Nkv=2、D=4，先忽略 bias。PyTorch Linear weight 使用 [out,in]：

层构造weight shape参数数
q_projLinear(H,Nq*D)[16,16]256
k_projLinear(H,Nkv*D)[8,16]128
v_projLinear(H,Nkv*D)[8,16]128
o_projLinear(Nq*D,H)[16,16]256

对应 MHA 的 Nkv=4 时，k_proj/v_proj 各为 [16,16]、各 256 参数。GQA 降低的是 K/V projection 参数；q_proj 和 o_proj 不因 Nkv 减少。

不能把一个已经训练好的 MHA checkpoint 随意删掉 K/V heads 就宣称得到等价 GQA。head 数是模型架构和权重 shape 的一部分；原始 GQA 工作讨论了从 MHA checkpoint 转换并继续训练的方法。本课只实现已经按 GQA 结构定义好的推理。

7. KV Cache 字节：为什么对 on-device decode 重要

KV Cache 在一次生成请求中，为每一层保存已经处理过的 K 和 V。Q 只服务当前计算，不缓存。暂不考虑 allocator 对齐和元数据，容量公式是：

KV bytes = 2 * B * L * Nkv * S_cache * D * bytes_per_element
           ↑ K和V

L 是 decoder layer 数；S_cache 是缓存的 token 数。例：B=1、L=32、S_cache=1024、D=128、FP16=2 bytes：

MHA: Nkv=32
2*1*32*32*1024*128*2 = 536,870,912 bytes = 512 MiB

GQA: Nkv=8
2*1*32*8*1024*128*2  = 134,217,728 bytes = 128 MiB

节省 = 384 MiB；GQA/MHA 比例 = Nkv/Nq = 8/32 = 1/4

这里 MiB 是 2^20 bytes。Cache 应保存重复前的 [B,Nkv,S,D] K/V。若为了方便计算把 K/V 逻辑映射到 Nq heads，不能把这份展开结果当作 Cache 保存，否则会失去 GQA 的容量优势。

8. Prefill 与 decode：省容量不等于所有计算都按比例减少

阶段典型 query/key 长度GQA 的主要影响
full-sequence / prefillQ length≈S，K length≈S仍有 Nq 份 score 表；naive attention score 计算并不会仅因 Nkv 减少到原来的 Nkv/Nq
单步 decodeQ length=1，K length=S_cache每步需读取历史 K/V；较少的 Nkv 显著降低 Cache 容量和要读取的数据量

因此 GQA 对 decoder inference 的价值不仅是“显存数字更小”，还包括降低每步从内存读取历史 K/V 的带宽压力。on-device 系统尤其受内存容量、带宽和功耗约束。

但不要做过度承诺：端到端速度还受 attention kernel、projection、RoPE、FFN、量化、Cache layout 和硬件影响。仅根据 Nkv 比例不能直接断言整模型快 4 倍；必须在目标 runtime 上测量。

9. repeat_kv 是计算映射，不是模型新学出的数据

最容易理解的 PyTorch reference 是：

group_size = Nq // Nkv
K_for_compute = K.repeat_interleave(group_size, dim=1)
V_for_compute = V.repeat_interleave(group_size, dim=1)

# [B,Nq,Sq,D] @ [B,Nq,D,Sk]
scores = Q @ K_for_compute.transpose(-2,-1) / sqrt(D)
weights = softmax(masked_scores, dim=-1)
head_output = weights @ V_for_compute

repeat_interleave 按连续分组得到 [KV0,KV0,KV1,KV1]，正好对应 Q heads 0..3。它适合教学 reference，但可能实际复制数据。生产 kernel 可以直接按 group 映射或使用支持 GQA 的 fused attention，不必物化完整重复 tensor。

本课脚本只实现 full-sequence 的方形 causal attention，即 query length 与 key length 相同。decode 时 query length=1、key length=S_cache，还必须带上新 query 在全局序列中的位置偏移来构造 causal 关系；不能直接把方形 mask 的代码原样套用。该状态与 mask 组合在 0010 验收。

Hugging Face Qwen3 eager reference 使用 expand + reshape 的 repeat_kv 路径；PyTorch scaled_dot_product_attention 也提供 enable_gqa，但其支持范围与 backend 有约束。本课独立代码使用显式 reference，便于看清每个 axis，不把某个 fused backend 是否可用当作数学门禁。

10. 与真实 Qwen 风格实现对齐

q_proj: Linear(hidden_size, num_attention_heads * head_dim)
k_proj: Linear(hidden_size, num_key_value_heads * head_dim)
v_proj: Linear(hidden_size, num_key_value_heads * head_dim)
o_proj: Linear(num_attention_heads * head_dim, hidden_size)

num_key_value_groups = num_attention_heads // num_key_value_heads

这与本课的 Nq、Nkv、group_size 完全对应。真实 forward 还会在 score 前对 Q/K 应用 RoPE，在 decode 时更新 KV Cache，并可能选择 eager、SDPA 或 FlashAttention backend；这些连接先定位，RoPE 和 Cache 增量执行分别在 0008、0010 验收。

对后续 export/lowering，必须区分三层事实：模型语义是 Q head 到 KV group 的映射；PyTorch reference 可能显示 repeat/expand；目标 runtime 可能把它融合进 attention kernel。图里出现 repeat 不等于设备一定真的复制了完整 Cache。

11. 常见错误与正确性不变量

错误为什么错
要求 Nkv % Nq == 0方向反了；必须是 Nq % Nkv == 0
用 q_head % Nkv 映射会得到交错映射 0,1,0,1；本课/常见 repeat_kv 是连续分组 0,0,1,1
把 Q 也减少到 Nkv heads那不再是保持 Nq query heads 的 GQA
head outputs 求平均MHA/GQA 通常 concat/merge 后经 o_proj，不是平均
Cache 保存 expanded K/V容量回到 Nq heads，破坏 GQA 的核心推理优势
认为 GQA score tensor 是 Nkv heads每个 Q head 仍有独立 score，因此是 Nq heads
只测 output shape错误的 head 映射仍可能产生相同 shape

应检查：具体 head 映射；MHA/GQA/MQA 三个边界；同组共享 K/V 但各 Q 可有不同 weights；未来 token 不影响过去；merge 顺序；Cache 字节比例。
