0004：谁计算，谁求梯度，谁修改参数

本课只训练一个标量模型：prediction = scale * x + bias。x 是输入，scale 是缩放参数，bias 是偏置参数，prediction 是预测值。我们用它把 nn.Module、nn.Parameter、forward、backward 和 optimizer 的职责彻底拆开。

1. 进入条件与本节成果

可以直接使用：你会标量乘加、平方、简单导数、Tensor dtype/device 和最大误差。

必须从零解释：参数注册、动态计算图、梯度累积、优化器更新和 finite difference（有限差分）验证。

本节成果：实现一个有两个可训练参数的 Module，完成一次训练步骤，并证明 autograd 给出的 scale.grad 与有限差分近似一致。

2. 先看全部具体数字

名称数值含义
x2输入，不是模型参数。
target10目标值，希望 prediction 接近它。
scale3可训练参数。
bias0可训练参数。
prediction = scale * x + bias
           = 3 * 2 + 0
           = 6

loss = (prediction - target)^2
     = (6 - 10)^2
     = 16

loss 是损失，一个衡量预测与目标差距的标量。这里使用 squared error（平方误差）。

3. nn.Module：组织计算与注册状态

class ScalarAffine(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.scale = torch.nn.Parameter(torch.tensor(3.0))
        self.bias = torch.nn.Parameter(torch.tensor(0.0))

    def forward(self, x):
        return self.scale * x + self.bias

nn 是 neural network 的缩写。nn.Module 是 PyTorch 模型和层的基础容器；它追踪挂在对象上的子 Module 与 Parameter。forward 描述输入怎样变成输出。

调用时写 prediction = model(x)，不要直接写 model.forward(x)。model(x) 会经过 Module 的调用机制，再执行 forward。

关键边界：forward 使用参数计算输出，但不会因为被调用就自动修改 scale 或 bias。

4. nn.Parameter：被 Module 注册的可训练 Tensor

nn.Parameter 是一种 Tensor。把它赋给 Module 属性后，Module 会把它登记在 named_parameters() 和 parameters() 中；优化器通常从这里取得要更新的对象。

for name, parameter in model.named_parameters():
    print(name, parameter.shape, parameter.requires_grad)

# scale torch.Size([]) True
# bias  torch.Size([]) True

torch.Size([]) 表示 rank 0 的标量 Tensor。requires_grad=True 表示在默认 grad mode（梯度模式）下，相关运算需要被 autograd 追踪。

普通 Tensor 即使写了 requires_grad=True，如果没有包装成 Parameter 并正确注册，也不会自动出现在 model.parameters() 中。它可以得到梯度，但默认 optimizer 不知道要更新它。

5. forward 阶段到底保存什么

autograd 是 automatic differentiation（自动微分）系统。当至少一个输入需要梯度时，PyTorch 在运行 Tensor 运算的同时记录这些运算之间的关系，形成用于反向计算的图。

prediction = model(x)                 # forward
loss = (prediction - target).pow(2)  # 继续构图

图记录的是类似下面的关系：

scale --multiply--+
x -----/          |
                  +--add bias--> prediction --subtract target--> square--> loss

这里的 forward 指从输入到 prediction/loss 的前向计算过程。它产生数值并记录求导所需关系；它不计算最终参数梯度，也不修改参数。

6. backward：从 loss 反向得到梯度

调用 loss.backward() 后，autograd 使用链式法则计算 loss 对 leaf Parameter（叶子参数，这里可先理解为反向计算最终要写入梯度的已注册参数）的导数，并把结果累积到各 Parameter 的 .grad。

本例逐步手算：

loss = (prediction - target)^2

d(loss)/d(prediction)
= 2 * (prediction - target)
= 2 * (6 - 10)
= -8

d(prediction)/d(scale) = x = 2
d(prediction)/d(bias)  = 1

d(loss)/d(scale) = -8 * 2 = -16
d(loss)/d(bias)  = -8 * 1 = -8

d(loss)/d(scale) 读作“loss 对 scale 的导数”，也就是 scale 的梯度。

backward 的职责：计算并累积梯度。它不会替你重新定义 loss，也不会修改参数值。

7. optimizer.step：真正修改参数

optimizer 是优化器对象，保存要更新的 Parameter 引用和更新规则。本例使用 SGD（stochastic gradient descent，随机梯度下降），学习率 lr=0.1；lr 是 learning rate，控制单步更新幅度。

optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

new_parameter = old_parameter - lr * gradient

new_scale = 3 - 0.1 * (-16) = 4.6
new_bias  = 0 - 0.1 * (-8)  = 0.8

梯度为负时，普通正学习率 SGD 会减去负数，所以参数增大。更新后：

new_prediction = 4.6 * 2 + 0.8 = 10
new_loss = (10 - 10)^2 = 0
optimizer.step() 使用已经存在于 .grad 的梯度更新参数。若还没 backward，或者 grad 是旧值，它不会自动替你补算正确梯度。

8. zero_grad：为什么每轮要清梯度

PyTorch 默认把新梯度加到已有 .grad，而不是覆盖。这样做支持多个 loss 或多个 micro-batch（微批次）的梯度累积，但普通单步训练需要先清零：

optimizer.zero_grad()
prediction = model(x)
loss = (prediction - target).pow(2)
loss.backward()
optimizer.step()

若第一次 backward 得到 scale.grad=-16，不清零又对同一参数关系做一次等价 backward，grad 会累积为 -32。

9. finite difference：不用 autograd 检查梯度

finite difference（有限差分）通过轻微扰动参数，观察 loss 的变化来近似导数。令 epsilon（记作 ε）为很小的正数：

d(loss)/d(scale) ≈ [L(scale + ε) - L(scale - ε)] / (2 * ε)

L(...) 表示把指定 scale 代入后重新 forward 得到的 loss。使用 ε=0.001：

L(3.001) = (3.001*2 - 10)^2 = 15.984004
L(2.999) = (2.999*2 - 10)^2 = 16.016004

(15.984004 - 16.016004) / 0.002 ≈ -16

它与 autograd 的 scale.grad=-16 对齐。有限差分不是训练方法，而是验证梯度实现是否可信的测试工具。扰动参数时使用 torch.no_grad()，并在结束后恢复原值。

10. 推理时关闭什么

model.eval()
with torch.inference_mode():
    prediction = model(x)

model.eval() 把 Module 切换到 evaluation mode（评估模式），会影响 Dropout（训练时随机屏蔽部分激活）和 BatchNorm（使用批次统计量做归一化）等有训练/评估差异的层；它本身不关闭梯度记录。torch.inference_mode() 才会关闭反向图记录并减少相关开销。本课的小模型没有 Dropout/BatchNorm，但要先建立这两个动作职责不同的认识。
