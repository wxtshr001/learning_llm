## 4. 实现与系统边界

1.`x*cos + rotate_half(x)*sin` 本质上就是把二维旋转矩阵拆开写：
[ y_i        ]   [ cos_i  -sin_i ] [ x_i        ]
[ y_{i+D/2}  ] = [ sin_i   cos_i ] [ x_{i+D/2}  ]
展开就是：

y_i        = x_i * cos_i - x_{i+D/2} * sin_i
y_{i+D/2}  = x_i * sin_i + x_{i+D/2} * cos_i
而 x*cos + rotate_half(x)*sin 正好实现这个结果：

前半部分：x_i * cos_i + (-x_{i+D/2}) * sin_i

后半部分：x_{i+D/2} * cos_i + x_i * sin_i

所以它本质上就是：

把 (x_i, x_{i+D/2}) 这个二维点逆时针旋转一个角度。
RoPE 只是把高维向量拆成很多个二维对子，每一对用不同频率的角度旋转。


2.默认 RoPE 通常没有可学习参数
angles
emb
动态计算出的 cos, sin这些应该算activation

inv_freq：通常注册为 buffer，因为它是根据 base 和 head_dim 预先算好的常量，不参与训练。
base、head_dim、rotary_dim、max_position_embeddings、rope_scaling：属于 config，是模型超参数。
预计算好的 cos_cached、sin_cached：可以注册为 buffer，避免每步重复计算。

position_ids是state

3.形状与布局不变量  位置 0 恒等  范数保持

4.因为 RoPE 是逐 head 独立、逐维配对的操作，不跨 head 混合信息。
